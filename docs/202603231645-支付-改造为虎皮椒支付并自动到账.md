# 支付改造：虎皮椒支付自动到账

## 背景

原有充值流程为：

1. 用户创建订单。
2. 用户扫码静态收款码。
3. 用户点击“我已支付”。
4. 管理员收到邮件后手动审核。
5. 审核通过后为用户增加付费额度。

该流程依赖人工审核，到账慢，且支付体验较差。

## 本次改造

已将主流程改为虎皮椒支付自动下单、自动回调、自动到账：

1. 用户在内容中心选择充值套餐。
2. 前端调用 `/api/payment/create` 创建虎皮椒订单。
3. 后端调用虎皮椒下单接口，返回支付链接和二维码。
4. 用户完成支付后，虎皮椒异步回调 `/api/payment/callback/xunhupay`。
5. 后端验签成功后自动将订单置为 `paid`，并增加用户 `paid_quota_remaining`。
6. 前端通过 `/api/payment/status` 自动轮询支付状态，到账后自动刷新额度。

## 代码变更

主要修改文件：

- `backend/src/index.ts`

新增能力：

- 虎皮椒支付签名与响应验签
- 统一订单入账 helper，保证幂等
- 新接口：`POST /api/payment/callback/xunhupay`
- 新接口：`GET /api/payment/status`
- 新页面：`GET /payment/return`
- 用户中心充值弹窗改为自动下单 + 自动轮询到账

兼容保留：

- 旧的 `/api/payment/approve` 仍保留，避免历史人工审批链接失效
- 旧的管理员订单数据和统计逻辑仍可继续使用

## 需要配置的环境变量

后端 Worker 需要以下环境变量：

- `XUNHUPAY_APP_ID`
- `XUNHUPAY_APP_SECRET`
- `XUNHUPAY_API_BASE`（可选，默认 `https://api.xunhupay.com`）

建议作为 Wrangler secret / env 配置，不写入仓库。
