# 小红书上报逻辑说明

## 问题描述
同一篇文章生成和发布后上报了两条记录，而且标题不一样。后来移除 `clickPublish` 中的上报后，点击发布按钮状态不更新。

## 问题分析

### 上报点分布
代码中存在两个上报点：

1. **第一个上报点**（clickPublish 函数）
   - 时机：点击发布按钮后立即上报
   - 目的：让用户立即看到状态更新
   - URL：当前页面 URL（发布设置页）
   - 标题：从 sessionStorage 读取的标题

2. **第二个上报点**（URL 监听器）
   - 时机：检测到 URL 变化且包含 `published=true` 参数
   - 目的：确认发布真正成功
   - URL：发布成功后的真实文章 URL
   - 标题：从 sessionStorage 读取的标题

### 为什么需要两次上报？

小红书的发布流程比较特殊：
1. 点击"发布"按钮后，页面不会立即跳转
2. 需要等待一段时间（服务器处理）
3. 然后页面才会跳转到 `?published=true`

因此需要两个上报点：
- `clickPublish`：立即上报，让用户知道已经点击了发布（状态更新）
- URL 监听器：最终上报，确认发布成功（获取真实 URL）

### 为什么会重复上报？

之前的问题是两次上报都会创建新记录，导致数据库中有两条记录。

## 解决方案

### 正确的处理方式

1. **clickPublish 中上报**：
   - 立即上报，让用户看到状态更新
   - **不清除** sessionStorage 数据
   - 使用 `generatedId` 关联到同一条记录

2. **URL 监听器中上报**：
   - 最终上报，确认发布成功
   - **清除** sessionStorage 数据
   - 使用相同的 `generatedId` 更新同一条记录

### 关键代码

```typescript
// clickPublish 函数中
await reportArticlePublish({
    platform: 'xiaohongshu',
    title: finalTitle,
    url: window.location.href,
    status: 'published',
    extra: { sourceUrl, promptTokens, completionTokens, totalTokens },
    generatedId // 关键：使用 generatedId 关联记录
});

// 关键：不清除 sessionStorage 数据
// 让 URL 监听器在最终上报后再清除
```

```typescript
// URL 监听器中
await reportArticlePublish({
    platform: 'xiaohongshu',
    title: finalTitle,
    url: currentUrl, // 真实的文章 URL
    status: 'published',
    extra: { sourceUrl, promptTokens, completionTokens, totalTokens },
    generatedId // 使用相同的 generatedId 更新记录
});

// 清除 sessionStorage 数据
sessionStorage.removeItem('memoraid_pending_title');
sessionStorage.removeItem('memoraid_token_usage');
sessionStorage.removeItem('memoraid_generated_id');
```

### 后端处理

后端的 `reportArticlePublish` 函数应该：
1. 如果提供了 `generatedId`，则更新已有记录
2. 如果没有 `generatedId`，则创建新记录

这样两次上报会更新同一条记录，而不是创建两条记录。

## 数据流程

```
点击发布按钮
    ↓
clickPublish 执行
    ↓
显示"文章已发布"
    ↓
（不上报，等待 URL 变化）
    ↓
页面跳转到发布成功页
    ↓
URL 监听器检测到 published=true
    ↓
读取 sessionStorage 数据
    ↓
上报文章发布
    ↓
清除 sessionStorage 数据
```

## 技术细节

### URL 监听器的触发条件
```typescript
if (currentUrl.includes('published=true')) {
    // 检测到发布成功
    // 读取数据并上报
    // 清除 sessionStorage
}
```

### sessionStorage 数据管理
- `memoraid_pending_title`：文章标题
- `memoraid_generated_id`：生成记录 ID
- `memoraid_token_usage`：Token 消耗数据
- `memoraid_pending_source_url`：来源 URL

这些数据在 URL 监听器上报后统一清除，确保不会影响下一次发布。
