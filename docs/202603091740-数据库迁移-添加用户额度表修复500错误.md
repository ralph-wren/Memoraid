# 数据库迁移 - 添加用户额度表修复500错误

## 问题描述
插件加载时请求 `/api/user/quota` 接口返回 HTTP 500 错误,导致显示"剩余额度: 加载失败"。

## 问题原因
后端代码中查询 `user_quotas` 表,但该表在远程数据库中不存在。表定义在 `migration-quotas-payment.sql` 文件中,但没有执行到远程数据库。

## 解决方案

### 1. 更新 schema.sql
已将以下表定义添加到 `backend/schema.sql`:
- `user_quotas` - 用户额度表
- `payment_orders` - 支付订单表  
- `ai_usage_logs` - AI使用日志表

### 2. 创建迁移脚本
创建了 `backend/migrate-add-quotas.sql` 文件,包含所有需要的表和索引。

### 3. 执行迁移

#### 本地数据库(已完成)
```bash
cd backend
npx wrangler d1 execute memoraid-db --local --file=migrate-add-quotas.sql
```
✅ 本地执行成功

#### 远程数据库(需要执行)
```bash
cd backend
npx wrangler d1 execute memoraid-db --remote --file=migrate-add-quotas.sql
```

⚠️ 如果遇到认证错误,需要:
1. 重新登录: `npx wrangler login`
2. 或者使用 API Token: `npx wrangler d1 execute memoraid-db --remote --file=migrate-add-quotas.sql --env production`

### 4. 表结构说明

#### user_quotas 表
```sql
CREATE TABLE user_quotas (
  user_id TEXT PRIMARY KEY,
  free_quota_remaining INTEGER DEFAULT 10,  -- 免费额度剩余
  paid_quota_remaining INTEGER DEFAULT 0,   -- 付费额度剩余
  updated_at INTEGER DEFAULT (strftime('%s', 'now')),
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

#### payment_orders 表
```sql
CREATE TABLE payment_orders (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  amount REAL NOT NULL,              -- 支付金额
  quota_amount INTEGER NOT NULL,     -- 购买的额度数量
  status TEXT DEFAULT 'pending',     -- pending, paid, cancelled
  payment_url TEXT,
  created_at INTEGER DEFAULT (strftime('%s', 'now')),
  paid_at INTEGER,
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

#### ai_usage_logs 表
```sql
CREATE TABLE ai_usage_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL,
  generated_id TEXT,
  platform TEXT,
  model TEXT,
  prompt_tokens INTEGER DEFAULT 0,
  completion_tokens INTEGER DEFAULT 0,
  total_tokens INTEGER DEFAULT 0,
  created_at INTEGER DEFAULT (strftime('%s', 'now')),
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## 验证步骤

2. 检查控制台是否还有500错误
3. 确认额度显示正常

- 迁移过程中数据库会短暂不可用
