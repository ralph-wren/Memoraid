# 知乎发布修复 - 标题清理和文章统计

## 更新时间
2026-03-03 22:30

## 问题描述
1. 知乎发布的文章标题包含额外的通知文字,如 "(3 封私信 / 27 条消息)"
2. 知乎发布的文章标题过长,超过100个字符
3. 知乎发表的文章没有在后台统计(个人管理页面和管理员页面都看不到)

## 问题原因

### 问题1: 标题包含通知文字
当无法从标题输入框获取标题时,代码会 fallback 到 `document.title`,而知乎页面的 `document.title` 包含了通知信息:
```
"文章标题 (3 封私信 / 27 条消息) - 知乎"
```

### 问题2: 标题过长
没有对标题长度进行限制,导致超长标题显示不美观

### 问题3: 文章统计问题
文章上报流程:
1. 文章生成时上报一次(status: 'generated')
2. 文章发布时应该再次上报(status: 'published'),使用相同的generatedId更新记录
3. 可能的问题:发布按钮点击检测失败、URL识别失败、上报请求失败

## 解决方案

### 1. 添加标题清理函数

在 `src/content/zhihu.ts` 中添加 `cleanTitle` 函数:

```typescript
// 清理标题,移除通知信息等额外文字
const cleanTitle = (title: string): string => {
  if (!title) return '';
  // 移除知乎页面标题中的通知信息,如 "(3 封私信 / 27 条消息)"
  let cleaned = title
    .replace(/\(\d+\s*封私信\s*\/\s*\d+\s*条消息\)/g, '')  // 移除通知信息
    .replace(/\s*-\s*知乎.*$/g, '')  // 移除 "- 知乎" 后缀
    .trim();
  
  // 限制标题长度为100个字符(知乎标题输入框的限制)
  if (cleaned.length > 100) {
    cleaned = cleaned.substring(0, 100) + '...';
  }
  
  return cleaned;
};
```

### 2. 修改标题获取逻辑

在 `reportOnce` 函数中使用 `cleanTitle` 清理标题:

```typescript
const reportOnce = (trigger: string, publishedUrl: string) => {
  if (hasReported) return;
  hasReported = true;
  
  // 优先使用缓存的标题
  const pendingTitle = sessionStorage.getItem('memoraid_pending_title');
  let rawTitle = pendingTitle || getCurrentTitle() || document.title || '未命名文章';
  // 清理标题,移除通知等额外信息
  const finalTitle = cleanTitle(rawTitle);
  
  console.log('[Memoraid Zhihu] 准备上报文章:', {
    trigger,
    url: publishedUrl,
    title: finalTitle,
    rawTitle,
    pendingTitle
  });
  
  // 如果成功上报，清除保存的标题
  if (pendingTitle) {
    sessionStorage.removeItem('memoraid_pending_title');
  }

  reportArticlePublish({
    platform: 'zhihu',
    title: finalTitle,
    url: publishedUrl,
    status: 'published',
    extra: { trigger },
    generatedId: sessionStorage.getItem('memoraid_generated_id') || undefined
  }).then(() => {
    console.log('[Memoraid Zhihu] 文章上报成功');
  }).catch((err) => {
    console.error('[Memoraid Zhihu] 文章上报失败:', err);
  });
};
```

## 清理规则

`cleanTitle` 函数会:
1. 移除通知信息: `(3 封私信 / 27 条消息)` 格式的文字
2. 移除网站后缀: `- 知乎` 及其后面的所有内容
3. 限制长度: 超过100个字符会截断并添加 `...`
4. 清理前后空白字符

## 文章上报流程

### 生成阶段
1. 用户在插件popup点击"知乎"按钮
2. Background script生成文章内容
3. 调用 `reportArticlePublish` 上报文章(status: 'generated')
4. 保存 `generatedId` 到 `pending_zhihu_publish`
5. 打开知乎编辑页面

### 发布阶段
1. Content script从 `pending_zhihu_publish` 读取数据
2. 将 `generatedId` 保存到 `sessionStorage`
3. 自动填充标题和内容
4. 用户点击"发布"按钮
5. Content script检测到发布按钮点击
6. 等待页面跳转到文章页面
7. 从URL提取文章ID
8. 调用 `reportArticlePublish` 更新文章(status: 'published',使用相同的generatedId)

3. **看到"文章上报失败"** - 说明后端API有问题或网络请求失败

## 后端API说明

`/api/articles/report` 接口处理流程:
1. 验证用户身份(支持匿名用户)
2. 检查用户额度(每篇文章消耗1次额度)
3. 获取或创建平台记录
4. 创建或更新账号信息
5. 插入或更新文章记录(使用generatedId关联)
6. 扣除相应额度(只为新文章扣除)

### 可能的原因分析
1. **代码执行中断**: 知乎生成流程可能在到达 `reportArticlePublish()` 之前就 throw 了异常或 return
2. **平台参数错误**: 知乎的 `platform` 参数值可能不是 `'zhihu'`
3. **不同的代码路径**: 知乎可能走了不同的生成流程，没有经过 `startArticleGenerationAndPublish` 函数
4. **异步问题**: 可能存在 Promise 没有正确 await 导致代码跳过

### 对比微信和知乎
两个平台的处理流程应该完全一致：
1. `handleInitiateProcess(platform, tabId)` 被调用
2. 抓取页面内容
3. 调用 `startArticleGenerationAndPublish(extraction, platform)`
4. AI 生成文章
5. 调用 `reportArticlePublish()` 上报（status: 'generated'）
6. 调用 `handlePublishToZhihu()` 或 `handlePublishToWeixin()`
7. 打开编辑页面

如果知乎没有调用 `reportArticlePublish()`，说明步骤5之前就出问题了。
