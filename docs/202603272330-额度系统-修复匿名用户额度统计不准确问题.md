# 匿名用户额度统计不准确问题分析与修复

## 问题描述

匿名用户 `anon_1773911230347_j6dsy6mwi@anonymous.com` 出现以下异常情况：
- 配置的免费额度：5次
- 管理后台显示已生成：12篇文章
- 实际数据库记录：16篇文章（全部为 `published` 状态）
- AI使用日志记录：0条
- 用户额度表：无记录

## 问题根源分析

### 1. 文章状态问题
```sql
-- 查询结果显示所有16篇文章状态都是 'published'
SELECT status, COUNT(*) as count 
FROM articles a 
JOIN accounts acc ON a.account_id = acc.id 
WHERE acc.user_id = 'anon_1773911230347_j6dsy6mwi' 
GROUP BY status;

-- 结果：
-- status: published, count: 16
```

**问题**：所有文章状态都是 `published`，没有 `generated` 状态的文章。

### 2. 额度扣除逻辑
根据代码 `backend/src/index.ts` 第 3927-3933 行：

```typescript
// 【修复】只对 status='generated' 的新文章扣除额度
// 这样即使去重失败，'published' 状态的文章也不会重复扣除
if (!existingArticle && status === 'generated') {
    newArticlesCount++;
    console.log(`[Article Report] 新生成的文章，将扣除额度: articleId=${articleId}`);
} else if (existingArticle) {
    console.log(`[Article Report] 已存在文章，不扣除额度: articleId=${articleId}`);
} else if (status !== 'generated') {
    console.log(`[Article Report] 非生成状态(${status})，不扣除额度: articleId=${articleId}`);
}
```

**问题**：
- 只有 `status='generated'` 的新文章才会扣除额度
- 但所有16篇文章的状态都是 `published`
- 因此没有任何文章被扣除额度
- `ai_usage_logs` 表中该用户的记录为 0

### 3. 前端上报逻辑问题
查看前端代码，发现插件在上报文章时可能直接使用了 `published` 状态，而不是 `generated` 状态。

### 4. 管理后台统计逻辑
管理后台显示的"12篇"可能是基于某个时间范围或其他筛选条件的统计，与实际数据库的16篇不一致。

## 问题影响

1. **额度绕过**：用户可以无限生成文章而不消耗额度
2. **统计不准确**：管理后台显示的数据与实际不符
3. **数据不一致**：文章数量、额度使用、日志记录三者不匹配

## 解决方案

### 已采用方案：兼容 published 状态的额度扣除（2026-03-27）

修改后端逻辑，只要是新文章（不存在于数据库），无论状态是 `generated` 还是 `published` 都扣除额度：

```typescript
// backend/src/index.ts 第 3926-3933 行
// 【修复2026-03-27】兼容 generated 和 published 状态的新文章扣除额度
// 只要是新文章（不存在于数据库），无论状态是 generated 还是 published 都扣除额度
// 这样可以防止用户通过直接上报 published 状态绕过额度限制
if (!existingArticle) {
    newArticlesCount++;
    console.log(`[Article Report] 新文章(status=${status})，将扣除额度: articleId=${articleId}`);
} else {
    console.log(`[Article Report] 已存在文章，不扣除额度: articleId=${articleId}, existingStatus=${existingArticle.status}`);
}
```

### 修复效果

1. **防止额度绕过**：无论前端上报什么状态，新文章都会扣除额度
2. **保持去重逻辑**：已存在的文章不会重复扣除额度
3. **向后兼容**：同时支持 `generated` 和 `published` 两种状态
