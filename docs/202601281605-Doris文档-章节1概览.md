# Doris 文档 —— 第 1 章 概览

## 1.1 产品定位
- Apache Doris 是一款 MPP 架构的实时数仓，面向高并发低延迟的分析查询。
- 主要解决明细级数据的近实时查询需求，同时兼顾批量分析与报表场景。

## 1.2 核心特性
- **列式存储 + 向量化执行**：提升扫描与计算效率。
- **多副本 + 高可用**：通过 BE 副本与 FE 元数据冗余保证服务连续性。
- **实时导入**：支持 Stream Load、Routine Load、Broker Load、CDC 等多种导入方式，满足分钟级甚至秒级可见。
- **SQL 兼容性**：遵循 MySQL 协议，易于接入现有生态。
- **弹性扩展**：BE 节点可按需水平扩容。

## 1.3 典型使用场景
- 用户行为明细分析与实时运营看板。
- 广告/推荐/风控类的特征拉取与指标查询。
- 运营报表与多维数据集 (OLAP) 分析。
- 数据湖加速：通过外表访问 HDFS/对象存储中的明细数据。

## 1.4 架构概览
- **FE (Frontend)**：负责元数据管理、查询解析、优化与调度，维护 Catalog 与事务。
- **BE (Backend)**：负责存储与执行，维护 Tablet 与数据分片，执行扫描、聚合、Join 等算子。
- **Broker/Sidecar**：为导入阶段提供外部存储访问能力（如 HDFS、S3 兼容对象存储）。
- **Tablet + Replica**：数据按照分区、Bucket（Hash）切分为 Tablet，并在多副本上冗余存储。

## 1.5 部署模式简述
- **生产集群**：多 FE（1 主多从）+ 多 BE，Broker 可按需部署。
- **弹性/云原生**：基于容器或 K8s 的算力池，结合对象存储实现计算存储分离。
- **单机/POC**：1 FE + 1 BE 快速试用。

## 1.6 与常见方案对比（简表）
- **vs ClickHouse**：Doris 更注重 MySQL 协议兼容与多导入方式；ClickHouse 在函数/引擎生态更丰富。
- **vs StarRocks**：两者同源，StarRocks 加强了查询优化与物化视图；Doris 社区活跃，发布节奏稳定。
- **vs Presto/Trino**：Doris 提供存储与计算一体的高性能明细查询；Presto/Trino 更偏向计算引擎，依赖外部存储。
