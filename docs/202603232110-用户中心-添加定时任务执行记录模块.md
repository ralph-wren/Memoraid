# 用户中心添加定时任务执行记录模块

## 更新时间
2026-03-23 21:10

## 问题描述
用户中心需要添加定时任务执行记录模块，方便用户查看定时任务的执行历史、状态和结果。

## 解决方案

### 1. 数据库设计

#### 创建执行记录表
新增`task_execution_logs`表用于存储每次定时任务的执行详情。

**表结构：**
```sql
CREATE TABLE task_execution_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,   -- 自增ID
  task_id TEXT NOT NULL,                  -- 关联的任务ID
  user_id TEXT NOT NULL,                  -- 用户ID
  task_name TEXT NOT NULL,                -- 任务名称（冗余存储）
  status TEXT NOT NULL,                   -- 执行状态：success/failed/running
  started_at INTEGER NOT NULL,            -- 开始时间戳（毫秒）
  completed_at INTEGER,                   -- 完成时间戳（毫秒）
  duration INTEGER,                       -- 执行时长（毫秒）
  articles_generated INTEGER DEFAULT 0,   -- 生成的文章数量
  articles_published INTEGER DEFAULT 0,   -- 成功发布的文章数量
  error_message TEXT,                     -- 错误信息
  details TEXT,                           -- 详细信息（JSON格式）
  created_at INTEGER NOT NULL
);
```

**索引：**
- `task_id` - 按任务查询
- `user_id` - 按用户查询
- `status` - 按状态筛选
- `started_at` - 时间排序

### 2. 前端页面改造

```html

```

#### 执行记录表格
显示以下信息：
- 任务名称
- 执行状态（成功/失败/运行中）
- 生成/发布数量
- 执行耗时
- 执行时间
- 错误信息

#### 分页功能
- 每页显示20条记录
- 支持上一页/下一页
- 显示当前页码和总页数

### 3. 后端API实现

#### GET /api/task-execution-logs
获取用户的定时任务执行记录（支持分页）

**请求参数：**
- `limit`: 每页数量（默认20）
- `offset`: 偏移量（默认0）

**响应数据：**
```json
{
  "logs": [
    {
      "id": 1,
      "task_id": "uuid",
      "task_name": "每日新闻发布",
      "status": "success",
      "started_at": 1234567890000,
      "completed_at": 1234567900000,
      "duration": 10000,
      "articles_generated": 5,
      "articles_published": 5,
      "error_message": null
    }
  ],
  "total": 100,
  "limit": 20,
  "offset": 0
}
```
