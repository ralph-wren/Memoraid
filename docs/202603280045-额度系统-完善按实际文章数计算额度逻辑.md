# 额度系统 - 完善按实际文章数计算额度逻辑

## 问题背景

在之前的额度系统优化中，我们已经实现了按照实际生成的文章数来计算额度使用，但需要进一步明确以下规则：

1. **免费用户超额使用**：如果免费用户生成的文章数超过免费额度，应该按实际显示（如 7/5），不进行修复
2. **付费用户额度优先级**：付费用户应该优先使用免费额度，免费额度用完后再使用付费额度
3. **数据一致性检查**：如果实际使用的付费额度与数据库记录不一致，应该显示警告图标⚠️

## 用户反馈

用户提出的具体要求：
- "如果是免费用户，实际生成文章比额度多的，就按实际来不进行修复，比如免费用户生成了7篇文章，那么免费额度就写成 7/5"
- "如果是付费用户，优先使用免费额度，再扣除付费额度"

## 解决方案

### 1. 额度计算逻辑

在管理后台的用户列表渲染中，按照以下逻辑计算额度：

```javascript
// 【修改2026-03-28】按照实际生成的文章数来计算额度使用
const totalArticles = u.total_articles || 0;
const paidTotal = u.paid_quota_total || 0;
const paidRemaining = u.paid_quota_remaining || 0;
const paidUsed = paidTotal - paidRemaining;

// 优先使用免费额度，再使用付费额度
let freeUsed = 0;
let actualPaidUsed = 0;

if (totalArticles <= limit) {
    // 文章数未超过免费额度，全部算免费
    freeUsed = totalArticles;
    actualPaidUsed = 0;
} else {
    // 文章数超过免费额度，超出部分算付费
    freeUsed = limit;
    actualPaidUsed = totalArticles - limit;
}

const freeRemaining = Math.max(0, limit - freeUsed);
const freeQuotaText = `${freeRemaining}/${limit}`;

// 付费额度：如果实际使用超过了付费总额度，显示负数
const actualPaidRemaining = paidTotal - actualPaidUsed;
const paidQuotaText = `${actualPaidRemaining}/${paidTotal}`;
```

### 2. 数据一致性检查

添加数据一致性检查，如果实际使用的付费额度与数据库记录不一致，显示警告图标：

```javascript
// 【新增2026-03-28】数据一致性检查
// 检查：实际使用的付费额度 是否等于 数据库记录的已使用付费额度
const dataConsistent = actualPaidUsed === paidUsed;
const warningIcon = dataConsistent ? '' : '<span style="color:#f59e0b;margin-left:4px" title="数据不一致：实际使用 ' + actualPaidUsed + ' 次，记录使用 ' + paidUsed + ' 次">⚠️</span>';
```

### 3. 显示效果

- **免费额度**：显示为 `剩余/总额度`，如果超额使用会显示负数（如 -2/5）
- **付费额度**：显示为 `剩余/总充值`，如果数据不一致会显示⚠️图标
- **累计文章**：显示用户累计生成的文章总数

## 示例场景

### 场景1：免费用户超额使用
- 用户类型：匿名用户（免费额度5篇）
- 实际生成：7篇文章
- 显示：免费额度 `-2/5`（红色），付费额度 `0/0`

### 场景2：付费用户正常使用
- 用户类型：GitHub用户（免费额度20篇）
- 实际生成：12篇文章
- 付费总额度：100篇
- 显示：免费额度 `8/20`（绿色），付费额度 `100/100`（绿色）

### 场景3：付费用户数据不一致
- 用户类型：GitHub用户（免费额度20篇）
- 实际生成：12篇文章
- 付费总额度：100篇，剩余90篇
- 理论：应该使用0篇付费额度（12篇都在免费额度内）
- 实际：数据库记录已使用10篇付费额度
- 显示：免费额度 `8/20`（绿色），付费额度 `100/100 ⚠️`（警告图标）

## 注意事项

1. **免费用户超额不修复**：按照用户要求，免费用户超额使用时不进行数据修复，直接显示实际值
2. **付费用户数据不一致**：如果付费用户的数据不一致，需要进一步调查原因，可能是历史数据问题
3. **额度扣除时机**：只有在文章上报时才扣除额度，AI聊天不扣除额度
4. **文章计数规则**：只要AI返回标题就算一篇文章，不管是否生成完毕或发布
