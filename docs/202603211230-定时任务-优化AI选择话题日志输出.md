# 定时任务 - 优化 AI 选择话题日志输出

## 问题描述

在定时任务执行日志中发现：
- AI 返回了 2 个话题选择
- 但最终只匹配成功 1 个话题
- 日志中缺少关键的匹配失败信息，无法判断第二个话题为什么没有匹配上

## 原因分析

日志输出不够详细：
1. 没有显示每个 URL 的匹配结果（成功/失败）
2. 匹配失败时没有输出警告信息
3. 最终结果的日志输出重复且冗余

## 解决方案

优化 `src/background/scheduler.ts` 中的日志输出逻辑：

1. **保留匹配过程日志**：在 URL 匹配时输出每个 URL 的匹配结果
   - 成功：`✅ [序号] 匹配成功: 文章标题`
   - 失败：`⚠️ [序号] 无法匹配 URL: xxx`

2. **简化最终结果日志**：
   - 移除重复的日志输出
   - 保留选择理由和 URL 信息，方便调试

3. **日志输出顺序**：
   ```
   🔍 开始匹配 N 个 URL...
   ✅/⚠️ 每个 URL 的匹配结果
   ✅ 最终选择 X 个话题（AI 返回 Y 个）
   ✅ 匹配成功的文章列表（含理由和 URL）
   ```

## 代码改动

修改文件：`src/background/scheduler.ts`

```typescript
// 在 URL 匹配过程中输出每个结果
const selectedArticles = selections
  .map((sel, idx) => {
    const article = articles.find(a => a.url === sel.url);
    if (!article) {
      // 匹配失败时输出警告
      taskLog(task.id, 'warn', `⚠️ [${idx + 1}] 无法匹配 URL: ${sel.url}`);
    } else {
      // 匹配成功时输出成功信息
      taskLog(task.id, 'success', `✅ [${idx + 1}] 匹配成功: ${article.title}`);
    }
    return article ? { ...article, reason: sel.reason } : null;
  })
  .filter((article): article is { title: string; url: string; reason: string } => article !== null)
  .slice(0, articleCount);

// 输出最终结果（简化，去除重复）
await taskLog(task.id, 'success', `✅ 最终选择 ${selectedArticles.length} 个话题（AI 返回 ${selections.length} 个）`);

// 输出匹配成功的文章详情
await taskLog(task.id, 'info', `✅ 匹配成功的文章:`);
selectedArticles.forEach((article, i) => {
  taskLog(task.id, 'info', `  ${i + 1}. ${article.title}`);
  taskLog(task.id, 'info', `     💡 选择理由: ${article.reason}`);
  taskLog(task.id, 'info', `     🔗 URL: ${article.url}`);
});
```

## 预期效果

下次执行定时任务时，日志会更清晰地显示：
1. 每个 URL 是否匹配成功
2. 如果匹配失败，会显示具体的 URL
3. 最终选择的文章列表及选择理由

这样可以更容易排查为什么某些话题没有被选中。

## 测试建议

等待下次定时任务自动执行，观察日志输出是否包含：
- 每个 URL 的匹配结果
- 匹配失败的 URL 详情
- 最终选择的文章及理由
