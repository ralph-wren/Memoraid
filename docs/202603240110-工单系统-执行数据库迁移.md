# 工单系统 - 执行数据库迁移

## 问题描述
用户访问工单反馈页面时出现数据库错误：
```
加载失败: D1_ERROR: no such column: is_admin at offset 7: SQLITE_ERROR
```

## 问题原因
工单系统的数据库迁移文件 `0011_create_tickets.sql` 只在本地执行了，没有在远程Cloudflare D1数据库执行，导致 `tickets` 和 `ticket_messages` 表不存在。

## 解决方案
使用 `wrangler d1 execute` 命令在远程数据库执行迁移文件。

## 执行命令
```bash
npx wrangler d1 execute memoraid-db --remote --file=./migrations/0011_create_tickets.sql
```

## 执行结果
- 成功执行5条SQL语句
- 创建了 `tickets` 表（工单主表）
- 创建了 `ticket_messages` 表（消息表）
- 创建了3个索引：
  - `idx_tickets_user_id`
  - `idx_tickets_status`
  - `idx_ticket_messages_ticket_id`

## 数据库表结构

### tickets 表
- `id`: 工单ID（主键，自增）
- `user_id`: 用户ID
- `subject`: 工单主题
- `status`: 状态（open/replied/closed）
- `created_at`: 创建时间
- `updated_at`: 更新时间

### ticket_messages 表
- `id`: 消息ID（主键，自增）
- `ticket_id`: 工单ID（外键）
- `user_id`: 用户ID
- `message`: 消息内容
- `is_admin`: 是否管理员回复（0=用户，1=管理员）
- `created_at`: 创建时间

## 测试验证
访问以下页面验证工单系统功能：
- 用户中心工单页面：https://memoraid.dpdns.org/user#tickets
- 管理员后台工单管理：https://memoraid.dpdns.org/admin（用户反馈标签）

## 注意事项
以后添加新的数据库迁移时，记得同时在本地和远程执行：
- 本地：`npx wrangler d1 execute memoraid-db --local --file=./migrations/xxxx.sql`
- 远程：`npx wrangler d1 execute memoraid-db --remote --file=./migrations/xxxx.sql`
