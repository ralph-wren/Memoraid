# 支付清理审核残留逻辑

## 本次调整

- 删除后端废弃的人工审核接口：`POST /api/admin/orders/:id/audit`
- 删除废弃的人工通知与邮件审批接口：`POST /api/payment/notify`、`GET /api/payment/approve`
- 删除审批 token 相关辅助方法，支付链路统一只通过虎皮椒回调自动入账
- 管理后台支付记录筛选统一使用 `paid` / `cancelled`，同时兼容历史 `approved` / `rejected` 订单数据
- 邮件配置页改为“支付成功邮件配置”，去掉管理员收件箱配置，测试邮件直接发送到当前发件人邮箱
- 支付记录状态展示中，历史 `rejected` 文案统一按“已取消”展示，避免继续暴露审核语义

## 校验结果

- `./node_modules/.bin/tsc --noEmit`：通过
- `npm run build`：失败，仍然是当前本机 Node 18 环境加载 `undici` 时缺少全局 `File` 导致，非本次改动引入

## 说明

- 本次保留了对历史订单状态 `approved` / `rejected` 的兼容读取，避免旧数据在后台列表、统计和到账判断中异常。
- 新支付链路现在只保留自动到账逻辑，不再依赖任何人工审核入口。
