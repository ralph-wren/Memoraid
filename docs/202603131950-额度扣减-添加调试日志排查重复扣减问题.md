# 额度扣减问题 - 添加调试日志排查重复扣减

## 问题描述

用户反馈：付费用户每次生成文章时扣减了2个额度，但应该只扣减1个额度。

## 问题分析

### 可能的原因

1. **前端重复调用**：
   - "仅生成文章"功能调用一次 `reportArticlePublish`
   - "一键发布"功能可能调用两次（生成时一次，发布成功后一次）

2. **后端去重逻辑失效**：
   - 后端通过 `(account_id, article_id)` 组合判断文章是否已存在
   - 如果 `article_id` 每次都不同，会被认为是新文章
   - 如果 `account_id` 计算错误，也会导致去重失败

### 代码流程

**一键发布流程**：

1. **生成文章阶段**（`startArticleGenerationAndPublish`）：
   ```typescript
   const generatedId = await reportArticlePublish({
     platform: 'xiaohongshu',
     title: finalTitle,
     status: 'generated',
     // ...
   });
   ```
   - 生成临时ID：`gen_1710000000_abc123`
   - 后端创建文章记录，扣除1个额度

2. **发布成功阶段**（各平台 content script）：
   ```typescript
   const generatedId = sessionStorage.getItem('memoraid_generated_id');
   await reportArticlePublish({
     platform: 'xiaohongshu',
     title: finalTitle,
     status: 'published',
     generatedId, // 使用相同的ID
     // ...
   });
   ```
   - 使用相同的 `generatedId`
   - 理论上后端应该识别为同一篇文章，不扣除额度

### 后端去重逻辑

```typescript
// 检查文章是否已存在
const existingArticle = await env.DB.prepare(
  'SELECT id FROM articles WHERE account_id = ? AND article_id = ?'
).bind(accountDbId, articleId).first();

// 只有新文章才计数（用于扣除额度）
if (!existingArticle) {
  newArticlesCount++;
}
```

理论上这个逻辑是正确的，但实际扣除了2次额度。

## 解决方案

### 第一步：添加详细的调试日志

在后端 `backend/src/index.ts` 的文章处理逻辑中添加日志：

```typescript
// 【调试日志】记录文章处理情况
console.log(`[Article Report] 处理文章: articleId=${articleId}, accountDbId=${accountDbId}, exists=${!!existingArticle}, status=${status}`);

// 只有新文章才计数（用于扣除额度）
if (!existingArticle) {
  newArticlesCount++;
  console.log(`[Article Report] 新文章，将扣除额度: articleId=${articleId}`);
} else {
  console.log(`[Article Report] 已存在文章，不扣除额度: articleId=${articleId}`);
}
```

在额度扣除逻辑中添加日志：

```typescript
if (newArticlesCount > 0) {
  console.log(`[Article Report] 准备扣除额度: newArticlesCount=${newArticlesCount}, paidQuota=${paidQuota}, userId=${userId}`);
  
  // ... 扣除逻辑 ...
  
  console.log(`[Article Report] 已扣除付费额度: ${deductFromPaid} 次`);
} else {
  console.log(`[Article Report] 无新文章，不扣除额度`);
}
```

### 第二步：测试和验证

1. 部署后端代码
2. 使用"一键发布"功能生成并发布一篇文章
3. 查看后端日志（Cloudflare Workers 日志）
4. 分析日志输出：
   - 第一次调用：`exists=false`，应该扣除1个额度
   - 第二次调用：`exists=true`，应该不扣除额度
   - 如果第二次调用 `exists=false`，说明去重逻辑有问题

### 可能的问题点

1. **`generatedId` 传递失败**：
   - 检查 `sessionStorage` 是否正确保存和读取
   - 检查前端是否正确传递 `generatedId`

2. **`account_id` 计算错误**：
   - 第一次和第二次调用的 `platform` 可能不同
   - 导致生成不同的 `account_id`
   - 后端无法识别为同一账号的文章

3. **数据库查询时机问题**：
   - 可能存在并发问题
   - 第二次查询时第一次的插入还未完成
