# 额度系统 - 简化为只统计文章表动态计算

## 问题背景

之前的额度系统存在以下问题：
1. 在文章上报时扣除额度，需要维护 `ai_usage_logs` 表和 `user_quotas` 表
2. 数据可能不一致（文章表的实际数量 vs 记录的额度使用）
3. 逻辑复杂，需要在多个地方维护额度扣除逻辑

## 用户反馈

用户建议：
> "只统计文章明细的那个表，不看ai记录的了，统计更简单，比如文章有30篇，那么免费额度扣20，付费额度扣10，这样统计更精准"

## 解决方案

### 核心思路

**不再在文章上报时扣除额度，改为查询时动态计算**

计算规则：
1. 统计用户的文章总数（从 `articles` 表）
2. 前N篇（免费额度）算免费使用
3. 超出部分算付费使用
4. 动态计算剩余额度

### 优势

1. **数据源单一**：只看 `articles` 表，不依赖 `ai_usage_logs`
2. **逻辑简单**：不需要在文章上报时扣除额度
3. **数据准确**：文章表是唯一真实数据源，不会出现不一致
4. **易于维护**：只需要在查询时计算，不需要维护多个表

#### 2. 修改额度查询函数 `getUserQuotaSnapshot`

```typescript
async function getUserQuotaSnapshot(env: Env, userId: string): Promise<UserQuotaSnapshot> {
  // 1. 获取用户的免费额度上限
  const user = await env.DB.prepare(`
    SELECT provider FROM users WHERE id = ?
  `).bind(userId).first<{ provider?: string }>();
  
  const freeLimit = (user?.provider === 'anonymous') ? 5 : 20;
  
  // 2. 获取付费总额度（累计充值）
  const paidTotalRow = await env.DB.prepare(`
    SELECT COALESCE(SUM(quota_amount), 0) as paid_total
    FROM payment_orders
    WHERE user_id = ? AND status IN ('paid', 'approved')
  `).bind(userId).first<{ paid_total?: number }>();
  
  const paidTotal = Number(paidTotalRow?.paid_total || 0);
  
  // 3. 获取文章总数
  const articleCountRow = await env.DB.prepare(`
    SELECT COUNT(*) as total
    FROM articles a
    JOIN accounts ac ON a.account_id = ac.id
    WHERE ac.user_id = ?
  `).bind(userId).first<{ total?: number }>();
  
  const totalArticles = Number(articleCountRow?.total || 0);
  
  // 4. 计算剩余额度：前N篇算免费，超出部分算付费
  const freeUsed = Math.min(totalArticles, freeLimit);
  const freeQuota = freeLimit - freeUsed;
  
  const paidUsed = Math.max(0, totalArticles - freeLimit);
  const paidQuota = paidTotal - paidUsed;
  
  return {
    freeQuota,
    paidQuota,
    totalQuota: freeQuota + paidQuota,
  };
}
```

#### 3. 修改管理后台显示逻辑

// 计算免费额度使用情况

## 计算示例

### 示例1：匿名用户生成1篇文章
- 免费额度上限：5篇
- 文章总数：1篇
- 付费总额度：0篇
- **计算结果**：
  - 免费使用：min(1, 5) = 1篇
  - 免费剩余：5 - 1 = 4篇，显示 `4/5`
  - 付费使用：max(0, 1-5) = 0篇
  - 付费剩余：0 - 0 = 0篇，显示 `0/0`

## 优点总结

1. ✅ **逻辑简单**：只需要统计文章表，不需要维护额度记录
2. ✅ **数据准确**：文章表是唯一真实数据源
3. ✅ **易于理解**：前N篇免费，超出部分付费，一目了然
4. ✅ **无需迁移**：不需要修改历史数据
5. ✅ **性能良好**：查询时计算，不影响文章上报性能

## 注意事项

1. 如果用户删除文章，额度会自动恢复（因为是动态计算）
2. 付费额度可能为负数（超额使用），前端会显示红色警告
3. `user_quotas` 表的 `paid_quota_remaining` 字段不再更新，但保留不影响
