# 定时任务列表 - 修复API返回格式不一致问题

## 问题描述
用户反馈定时任务Tab显示"暂无定时任务"，但实际已在面板中创建了任务。后续又反馈"内容不全"。

## 问题原因
1. **API格式不一致**：前端组件使用 `GET /api/scheduled-tasks` 接口保存和加载任务，用户中心页面使用 `GET /api/scheduled-tasks/list` 接口显示任务列表，两个接口返回的数据格式不一致
2. **字段映射错误**：渲染函数使用了不存在的字段（`cron_expression`、`next_run_time`），导致显示内容不完整

## 解决方案

### 1. 统一API返回格式
修改 `/api/scheduled-tasks/list` 接口，使其返回与 `/api/scheduled-tasks` 相同的数据格式（驼峰命名）。

### 2. 修复渲染函数
重写 `renderScheduledTasks` 函数，正确使用API返回的字段：

**修改内容**：
- 移除对不存在字段的引用（`cron_expression`、`next_run_time`）
- 添加 `formatScheduleDesc` 函数，根据 `scheduleType` 生成执行周期描述
- 支持多个执行时间点（`executionTimes`）
- 平台代码转换为中文名称（weixin → 公众号）
- 显示上次执行时间和状态（带状态图标：✅成功、❌失败、⏳执行中）

**显示字段**：
| 字段 | 说明 | 示例 |
|------|------|------|
| 任务名称 | task.name | "每日热点推送" |
| 状态 | task.enabled | 运行中 / 已停止 |
| 目标平台 | task.platforms | 公众号、小红书 |
| 执行周期 | 根据scheduleType生成 | 每天 09:00、18:00 |
| 上次执行 | task.lastRunTime + lastRunStatus | 2026-03-23 22:30:15 ✅ |

### 3. 执行周期格式化逻辑
```javascript
function formatScheduleDesc(task) {
    // 支持多个执行时间点
    const executionTimes = task.executionTimes || [{ hour: task.hour, minute: task.minute }];
    const timeStrs = executionTimes.map(t => 
        String(t.hour).padStart(2, '0') + ':' + String(t.minute).padStart(2, '0')
    );
    
    if (task.scheduleType === 'daily') {
        return '每天 ' + timeStrs.join('、');  // 每天 09:00、18:00
    }
    
    if (task.scheduleType === 'weekly') {
        const days = task.weekdays.map(d => weekdayNames[d]).join('、');
        return '每' + days + ' ' + timeStrs.join('、');  // 每周一、周三 09:00
    }
    
    return '每 ' + task.intervalMinutes + ' 分钟';  // 每 60 分钟
}
```

## 数据流程说明
1. 用户在插件面板（`ScheduleSettings.tsx`）创建/编辑任务
2. 前端调用 `POST /api/scheduled-tasks` 或 `PUT /api/scheduled-tasks/:id` 保存到数据库
3. 数据库表 `scheduled_tasks` 使用下划线命名存储（如 `schedule_type`）
4. 用户访问 https://memoraid.dpdns.org/user 查看任务列表
5. 页面调用 `GET /api/scheduled-tasks/list` 获取任务
6. 接口将数据库字段转换为驼峰命名返回（如 `scheduleType`）
7. 前端 `renderScheduledTasks` 函数正确解析并渲染任务信息
