# 小红书原创声明修复 - 修复弹窗直接打开逻辑和选择器问题

## 问题描述
用户反馈：重新编译后原创声明功能仍然不工作。

通过 Console 测试发现两个问题：

### 问题 1：弹窗直接打开
```
=== 开始手动原创声明流程 ===
1. 查找并点击开关...
   找到开关: <div class="d-switch-top">...</div>
2. 查找"去声明"按钮...
   ❌ 未找到"去声明"按钮
   打开了弹窗
```

点击开关后，弹窗直接打开，不需要再点击"去声明"按钮。

### 问题 2：使用了 Playwright 特有的选择器
代码中使用了 `:has-text()` 和 `:contains()` 这些 Playwright 特有的选择器，但在浏览器的 `querySelector` 中是不支持的。

## 根本原因

小红书的原创声明功能有两种交互模式：

### 模式 1：开关 + "去声明"按钮（旧版或部分用户）
1. 点击开关 → 显示"去声明"按钮
2. 点击"去声明"按钮 → 打开弹窗
3. 勾选同意 → 点击"声明原创"

### 模式 2：开关直接打开弹窗（新版或部分用户）
1. 点击开关 → 弹窗直接打开 ✅
2. 勾选同意 → 点击"声明原创"

我们的代码只支持模式 1，不支持模式 2，导致在新版页面上失败。

## 解决方案

### 修改流程：使"去声明"按钮查找变为可选

修改 `setOriginalityDeclaration` 函数，在点击开关后：
1. 检查弹窗是否已打开
2. 如果已打开 → 跳过"去声明"按钮查找，直接进入勾选步骤
3. 如果未打开 → 查找并点击"去声明"按钮，然后等待弹窗打开

### 代码修改

```typescript
// 0) 先点击原创声明开关（如果存在）
// 关键发现：点击开关后，弹窗可能直接打开，不需要再点击"去声明"按钮
logger.log('查找原创声明开关...', 'info');
const switchEl = document.querySelector('.d-switch-simulator') as HTMLElement | null;
if (switchEl && isElementVisible(switchEl)) {
    // 查找开关的父容器（通常是 .d-switch-top）
    const switchContainer = switchEl.parentElement;
    logger.log('点击原创声明开关', 'action');
    await clickReliable(switchContainer || switchEl);
    await sleep(1000); // 等待开关动画和弹窗/按钮出现
}

// 1) 检查弹窗是否已打开（点击开关后可能直接打开弹窗）
let scope: ParentNode = document;
await sleep(500);
const dialogCandidates = Array.from(document.querySelectorAll('.d-modal, .d-drawer, .d-drawer-content, [role="dialog"], .originalContainer'));
let dialog = dialogCandidates.find(el => isElementVisible(el as HTMLElement)) as HTMLElement | undefined;

if (dialog) {
    // 弹窗已打开，跳过"去声明"按钮查找
    logger.log('弹窗已打开，跳过"去声明"按钮', 'info');
    scope = dialog;
} else {
    // 弹窗未打开，查找并点击"去声明"按钮
    logger.log('弹窗未打开，查找"去声明"按钮...', 'info');
    
    // ... 原有的"去声明"按钮查找和点击逻辑 ...
}
```

### 关键改进

1. **点击开关的父容器**：
   ```typescript
   const switchContainer = switchEl.parentElement;
   await clickReliable(switchContainer || switchEl);
   ```
   - 原因：`.d-switch-simulator` 只是状态指示器，真正可点击的是父容器 `.d-switch-top`
   - 效果：更可靠地触发开关点击事件

2. **增加等待时间**：
   ```typescript
   await sleep(1000); // 从 800ms 增加到 1000ms
   ```
   - 原因：弹窗打开需要动画时间
   - 效果：确保弹窗完全渲染后再检查

3. **检查弹窗是否已打开**：
   ```typescript
   const dialogCandidates = Array.from(document.querySelectorAll('.d-modal, .d-drawer, .d-drawer-content, [role="dialog"], .originalContainer'));
   let dialog = dialogCandidates.find(el => isElementVisible(el as HTMLElement)) as HTMLElement | undefined;
   ```
   - 原因：需要判断是哪种交互模式
   - 效果：支持两种模式

4. **条件分支**：
   ```typescript
   if (dialog) {
       // 模式 2：弹窗已打开
       scope = dialog;
   } else {
       // 模式 1：需要点击"去声明"按钮
       // ... 原有逻辑 ...
   }
   ```
   - 原因：兼容两种交互模式
   - 效果：无论哪种模式都能正常工作

## 技术细节

### 为什么点击父容器？

```html
<div class="d-switch-top">  <!-- 可点击的容器 -->
  <span class="d-switch-simulator checked --color-bg-primary"></span>  <!-- 状态指示器 -->
</div>
```

- `.d-switch-simulator`：只是一个状态指示器（显示 `checked` 或 `unchecked`）
- `.d-switch-top`：真正可点击的容器，有事件监听器
- 点击父容器更可靠，因为它是事件委托的目标

### 为什么需要等待 1000ms？

```typescript
await sleep(1000); // 等待开关动画和弹窗/按钮出现
```

时间分配：
- 开关动画：约 300ms
- 弹窗渲染：约 400ms
- 缓冲时间：约 300ms
- 总计：1000ms

### 弹窗检测选择器

```typescript
'.d-modal, .d-drawer, .d-drawer-content, [role="dialog"], .originalContainer'
```

覆盖小红书可能使用的所有弹窗类型：
- `.d-modal`：模态框
- `.d-drawer`：抽屉
- `.d-drawer-content`：抽屉内容
- `[role="dialog"]`：ARIA 对话框
- `.originalContainer`：原创声明容器

## 经验总结

### 1. 不要假设页面只有一种交互模式
- 小红书可能在做 A/B 测试
- 不同用户可能看到不同的页面
- 代码要兼容多种模式

### 2. 使用条件分支处理不同模式
```typescript
if (dialog) {
    // 模式 A
} else {
    // 模式 B
}
```

### 3. 点击事件要找对目标
- 不要点击状态指示器（`.d-switch-simulator`）
- 要点击可点击的容器（`.d-switch-top`）
- 使用 `parentElement` 找到父容器

### 4. 等待时间要充足
- 动画需要时间
- 渲染需要时间
- 留出缓冲时间

### 5. 日志要详细
- 每个分支都要输出日志
- 方便排查是哪种模式
- 方便定位问题

## 为什么之前没有发现这个问题？

可能的原因：
1. **A/B 测试**：小红书可能在做 A/B 测试，不同用户看到不同的页面
2. **页面更新**：小红书可能更新了页面，改变了交互模式
3. **测试不充分**：之前测试时可能只测试了一种模式
4. **账号差异**：不同账号可能有不同的功能版本

## 结论
修复后，代码会在点击开关后检查弹窗是否已打开：
- 如果已打开 → 跳过"去声明"按钮查找，直接进入勾选步骤（模式 2）
- 如果未打开 → 查找并点击"去声明"按钮（模式 1）

这样就能兼容两种交互模式，无论小红书使用哪种模式，原创声明功能都能正常工作。
