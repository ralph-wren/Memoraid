# 定时任务 - 修复发布超时被误判为成功的问题

## 问题描述

定时任务执行时，如果平台发布超时（120秒），日志会显示"⚠️ weixin 发布超时（120秒），继续下一个平台"，但最终统计仍然显示"成功 3 篇，失败 0 篇"，并发送成功通知邮件。

实际案例：
```
[20:40:36] [INFO   ] 📤 开始发布到: weixin...
[20:43:43] [WARN   ] ⚠️ weixin 发布超时（120秒），继续下一个平台
[20:43:43] [SUCCESS] ✅ [1/3] 话题处理完成
...
[20:50:22] [SUCCESS] 🎉 任务全部完成！成功 3 篇，失败 0 篇
[20:50:22] [SUCCESS] ✅ 邮件通知已发送
```

所有3篇文章都超时了，但仍然被统计为成功。

## 问题原因

在 `src/background/scheduler.ts` 中，发布超时的处理逻辑有问题：

```typescript
if (!publishCompleted) {
  await taskLog(task.id, 'warn', `⚠️ ${platform} 发布超时（120秒），继续下一个平台`);
  // 这里只是记录日志，没有抛出错误
}

// 无论是否超时，都会执行这里
successCount++;  // ❌ 错误：超时也被计入成功
```

超时后代码继续执行，`successCount++` 仍然会被执行，导致超时被误判为成功。

## 解决方案

修改超时处理逻辑，将超时情况抛出错误，让外层的 catch 块处理：

```typescript
if (!publishCompleted) {
  await taskLog(task.id, 'warn', `⚠️ ${platform} 发布超时（120秒），继续下一个平台`);
  // 超时算作失败，抛出错误让外层catch处理
  throw new Error(`${platform} 发布超时（可能需要重新登录）`);
}
```

同时，在 catch 块中也要抛出错误：

```typescript
} catch (e: any) {
  await taskLog(task.id, 'error', `❌ 发布到 ${platform} 失败: ${e.message}`);
  // 发布失败，抛出错误让外层catch处理
  throw e;
}
```

这样，当发布超时或失败时，会被外层的 try-catch 捕获，执行 `failCount++` 而不是 `successCount++`。

## 修改前后对比

### 修改前
```typescript
if (!publishCompleted) {
  await taskLog(task.id, 'warn', `⚠️ ${platform} 发布超时（120秒），继续下一个平台`);
}
// 继续执行，超时也算成功
successCount++;
```

### 修改后
```typescript
if (!publishCompleted) {
  await taskLog(task.id, 'warn', `⚠️ ${platform} 发布超时（120秒），继续下一个平台`);
  throw new Error(`${platform} 发布超时（可能需要重新登录）`);
}
// 只有真正成功才会执行到这里
successCount++;
```

## 效果

修复后，发布超时会被正确统计为失败：
- 日志显示：`❌ 发布到 weixin 失败: weixin 发布超时（可能需要重新登录）`
- 最终统计：`🎉 任务全部完成！成功 0 篇，失败 3 篇`
- 邮件通知会显示失败状态和失败原因

## 常见超时原因

1. **需要重新登录**：平台登录状态过期，无法自动发布
2. **网络问题**：页面加载缓慢或AI生成超时
3. **平台限制**：发布频率过高被限制
