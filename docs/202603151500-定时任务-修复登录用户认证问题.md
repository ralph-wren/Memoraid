# 定时任务 - 修复登录用户认证问题

## 问题描述

用户在登录状态下保存定时任务时，后端返回 `{"error":"Unauthorized"}` 或 `{"error":"任务不存在"}` 错误。

点击"立即执行"按钮时，任务一直无法执行，控制台显示"未执行任务"。

## 问题原因

### 问题 1：缺少 Authorization header
前端 `ScheduleSettings.tsx` 组件在调用后端 API 时，只发送了 `X-Anonymous-ID` header，没有发送 `Authorization: Bearer ${token}` header。

后端 API 的认证逻辑是：
1. 优先使用 `Authorization` header（通过 `getUserIdFromRequest` 函数获取 userId）
2. 如果没有 Authorization，则使用 `X-Anonymous-ID` header

但前端代码只实现了匿名用户的认证方式，导致登录用户的 token 没有被发送到后端。

### 问题 2：新任务判断逻辑错误
前端在保存任务时，使用了错误的逻辑判断是新任务还是更新任务：
```typescript
const isNew = !tasks.find(t => t.id === task.id);
```

这个判断不准确，因为新添加的任务也在 `tasks` 数组中，导致前端总是使用 PUT 方法，而后端数据库中还没有这个任务，所以返回"任务不存在"。

### 问题 3：调度器仍从本地存储读取任务
`scheduler.ts` 中的 `runTaskById` 和 `handleAlarm` 函数仍然从 `settings.scheduledTasks` 读取任务，但任务已经迁移到后端数据库中了，导致无法找到任务。

## 解决方案

### 1. 添加统一的认证 headers 构建函数

在 `ScheduleSettings.tsx` 中添加 `getAuthHeaders()` 函数：

```typescript
// 构建认证 headers：优先使用 token，否则使用 anonymousId
const getAuthHeaders = (): Record<string, string> => {
  const headers: Record<string, string> = {};
  if (settings.sync?.token) {
    // 已登录用户：使用 Authorization Bearer token
    headers['Authorization'] = `Bearer ${settings.sync.token}`;
  } else if (anonymousId) {
    // 匿名用户：使用 X-Anonymous-ID
    headers['X-Anonymous-ID'] = anonymousId;
  }
  return headers;
};
```

### 2. 修改所有 API 调用

将所有后端 API 调用的 headers 改为使用 `getAuthHeaders()`：

- `loadTasksFromBackend()` - 加载任务列表
- `saveTaskToBackend()` - 保存任务
- `deleteTask()` - 删除任务

### 3. 修复新任务判断逻辑

改用"先尝试 PUT，失败则改用 POST"的策略：

```typescript
// 先尝试 PUT（更新已存在的任务）
response = await fetch(url, {
  method: 'PUT',
  headers: {
    'Content-Type': 'application/json',
    ...getAuthHeaders(),
  },
  body: JSON.stringify(task),
});

// 如果返回 404（任务不存在），则改用 POST 创建新任务
if (response.status === 404) {
  url = `${backendUrl}/api/scheduled-tasks`;
  response = await fetch(url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      ...getAuthHeaders(),
    },
    body: JSON.stringify(task),
  });
}
```

这样可以自动处理新任务和更新任务的情况，无需手动判断。

### 4. 修改调度器从后端 API 获取任务

修改 `scheduler.ts` 中的两个函数：

#### 4.1 修改 `runTaskById` 函数
从后端 API 获取任务信息，而不是从本地存储读取：

```typescript
export async function runTaskById(taskId: string) {
  try {
    // 从后端 API 获取任务信息
    const settings = await getSettings();
    const backendUrl = settings.sync?.backendUrl || 'https://memoraid.dpdns.org';
    
    // 构建认证 headers
    const headers: Record<string, string> = {};
    if (settings.sync?.token) {
      headers['Authorization'] = `Bearer ${settings.sync.token}`;
    } else if (settings.anonymousId) {
      headers['X-Anonymous-ID'] = settings.anonymousId;
    }

    const response = await fetch(`${backendUrl}/api/scheduled-tasks`, { headers });
    const data = await response.json();
    const task = data.tasks.find((t: ScheduledTask) => t.id === taskId);
    
    if (task) {
      executeTask(task);
    }
  } catch (error) {
    console.error(`[Scheduler] 获取任务失败:`, error);
  }
}
```

#### 4.2 修改 `handleAlarm` 函数
定时检查时也从后端 API 获取任务列表：

```typescript
async function handleAlarm(alarm: chrome.alarms.Alarm) {
  if (alarm.name !== CHECK_ALARM_NAME) return;

  try {
    // 从后端 API 获取任务列表
    const settings = await getSettings();
    const backendUrl = settings.sync?.backendUrl || 'https://memoraid.dpdns.org';
    
    // 构建认证 headers
    const headers: Record<string, string> = {};
    if (settings.sync?.token) {
      headers['Authorization'] = `Bearer ${settings.sync.token}`;
    } else if (settings.anonymousId) {
      headers['X-Anonymous-ID'] = settings.anonymousId;
    }

    const response = await fetch(`${backendUrl}/api/scheduled-tasks`, { headers });
    const data = await response.json();
    const enabledTasks = data.tasks.filter((t: ScheduledTask) => t.enabled);

    const now = new Date();
    for (const task of enabledTasks) {
      if (shouldRunTask(task, now)) {
        await executeTask(task);
      }
    }
  } catch (error) {
    console.error('[Scheduler] 检查任务时出错:', error);
  }
}
```
