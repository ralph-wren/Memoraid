# 定时任务完成后自动关闭所有页面

## 问题描述

定时任务执行时会打开多个浏览器标签页（热榜页面、文章详情页等），执行完成后这些标签页会一直保留，导致浏览器标签页堆积。

用户希望任务完成后自动关闭这些页面，避免手动清理。

## 解决方案

### 核心思路

1. 在任务执行过程中，追踪所有任务打开的标签页 ID
2. 任务完成时（成功或失败），统一关闭所有任务标签页
3. 只关闭任务打开的页面，不影响用户手动打开的其他页面

### 实现细节

#### 1. 追踪任务标签页

在 `executeTask` 函数中添加 `taskTabIds` 数组：

```typescript
async function executeTask(task: ScheduledTask) {
  // 追踪任务打开的所有标签页 ID
  const taskTabIds: number[] = [];
  
  try {
    // ... 任务执行逻辑
    
    // 打开文章页面时记录 tab ID
    const tab = await chrome.tabs.create({
      url: article.url,
      active: false,
    });
    
    if (tab.id) {
      taskTabIds.push(tab.id); // 记录标签页 ID
    }
    
    // ... 后续处理
  } catch (error) {
    // 错误处理
  } finally {
    // 任务结束时关闭所有标签页
    await closeAllTaskTabs(taskTabIds);
  }
}
```

#### 2. 关闭标签页函数

新增 `closeAllTaskTabs` 函数，批量关闭任务标签页：

```typescript
/**
 * 关闭所有任务相关的标签页
 * 只关闭本次任务打开的标签页，不影响用户手动打开的页面
 */
async function closeAllTaskTabs(taskTabIds: number[]): Promise<void> {
  try {
    if (taskTabIds.length === 0) {
      console.log('[Scheduler] 没有需要关闭的标签页');
      return;
    }

    // 过滤出仍然存在的标签页
    const existingTabs = await chrome.tabs.query({});
    const existingTabIds = new Set(existingTabs.map(tab => tab.id));
    
    const tabsToClose = taskTabIds.filter(id => existingTabIds.has(id));

    // 批量关闭标签页
    if (tabsToClose.length > 0) {
      await chrome.tabs.remove(tabsToClose);
      console.log(`[Scheduler] 已关闭 ${tabsToClose.length} 个任务标签页`);
    }
  } catch (error) {
    console.error('[Scheduler] 关闭标签页失败:', error);
    // 不抛出错误，避免影响任务完成状态
  }
}
```

#### 3. 调用时机

在任务完成时（成功或失败）都会调用关闭函数：

```typescript
// 成功完成
await updateTaskStatus(task.id, 'success');
await taskLog(task.id, 'success', `\n🎉 任务全部完成！成功 ${successCount} 篇，失败 ${failCount} 篇`);

// 关闭所有任务打开的页面
await taskLog(task.id, 'info', `🧹 正在关闭任务打开的 ${taskTabIds.length} 个页面...`);
await closeAllTaskTabs(taskTabIds);
await taskLog(task.id, 'success', `✅ 页面已全部关闭`);
```

```typescript
// 失败时也关闭
catch (error: any) {
  await taskLog(task.id, 'error', `❌ 任务失败: ${error?.message || String(error)}`);
  await updateTaskStatus(task.id, 'failed', error?.message || String(error));

  // 关闭所有任务打开的页面
  await taskLog(task.id, 'info', `🧹 正在关闭任务打开的 ${taskTabIds.length} 个页面...`);
  await closeAllTaskTabs(taskTabIds);
  await taskLog(task.id, 'success', `✅ 页面已全部关闭`);
}
```

### 关键改动

#### 移除了单篇文章处理完后立即关闭的逻辑

之前的代码：
```typescript
// ❌ 旧逻辑：每篇文章处理完立即关闭
await chrome.tabs.remove(tab.id);
```

现在改为：
```typescript
// ✅ 新逻辑：记录 tab ID，统一在任务结束时关闭
taskTabIds.push(tab.id);
```

## 优势

1. **避免标签页堆积**：任务完成后自动清理，保持浏览器整洁
2. **精准控制**：只关闭任务打开的页面，不影响用户手动打开的其他页面
3. **容错处理**：即使关闭失败也不影响任务状态，避免误报错误
4. **日志可见**：在任务日志中显示关闭页面的过程，方便用户了解

## 后续优化

### 页面加载超时重试机制（2026-03-15 20:40）

在实际使用中发现，微博等页面加载较慢，可能超过 20 秒导致超时错误。

优化方案：
1. 将超时时间从 20 秒增加到 30 秒
2. 添加重试机制：如果首次加载超时，自动刷新页面并重试一次
3. 在日志中显示重试过程，方便用户了解

```typescript
// 等待页面加载，增加超时时间到 30 秒，并添加重试机制
try {
  await waitForTabLoad(tab.id, 30000);
  await taskLog(task.id, 'success', `✅ 页面加载完成`);
} catch (loadError: any) {
  // 如果加载超时，重试一次
  await taskLog(task.id, 'warn', `⚠️ 页面加载超时，正在重试...`);
  try {
    // 刷新页面
    await chrome.tabs.reload(tab.id);
    await waitForTabLoad(tab.id, 30000);
    await taskLog(task.id, 'success', `✅ 页面加载完成（重试成功）`);
  } catch (retryError: any) {
    // 重试失败，抛出错误
    throw new Error(`页面加载失败: ${retryError.message || '超时'}`);
  }
}
```

这样可以大大提高任务成功率，减少因网络波动导致的失败。
