# 工单系统 - 修复管理员权限验证逻辑

## 问题描述

管理员后台访问工单列表时返回 403 Forbidden 错误，即使管理员已正确登录。

## 根本原因

系统存在两套独立的用户体系：

1. **系统管理员**：存储在 `admins` 表，通过 `/auth/admin/login` 登录
2. **普通用户**：存储在 `users` 表，通过 OAuth 登录

管理员登录时生成的 token 包含：
```javascript
{
  userId: admin.id,  // 来自 admins 表
  username: admin.username,
  role: 'system_admin',
  exp: Date.now() + 24 * 60 * 60 * 1000
}
```

但工单管理接口错误地使用这个 `userId` 去查询 `users` 表的 `is_admin` 字段：
```javascript
const user = await env.DB.prepare(
  'SELECT is_admin FROM users WHERE id = ?'
).bind(userId).first();  // userId 是 admins 表的ID，在 users 表中不存在
```

这导致查询结果为空，权限检查失败。

## 解决方案

### 1. 创建管理员权限验证辅助函数

在 `backend/src/index.ts` 中添加 `verifyAdminToken` 函数，直接检查 token 的 `role` 字段：

```typescript
// 验证系统管理员权限（检查token的role字段）
function verifyAdminToken(request: Request): { valid: boolean; error?: string } {
  const authHeader = request.headers.get('Authorization');
  if (!authHeader) {
    return { valid: false, error: 'Unauthorized' };
  }
  
  const token = authHeader.startsWith('Bearer ') ? authHeader.substring(7) : authHeader;
  if (!token.startsWith('mock_jwt_')) {
    return { valid: false, error: 'Unauthorized' };
  }
  
  try {
    const tokenPart = token.split('mock_jwt_')[1];
    const payload = JSON.parse(atob(tokenPart));
    
    if (payload.exp && payload.exp < Date.now()) {
      return { valid: false, error: 'Token expired' };
    }
    
    // 检查是否是系统管理员
    if (payload.role !== 'system_admin') {
      return { valid: false, error: 'Forbidden' };
    }
    
    return { valid: true };
  } catch (e) {
    return { valid: false, error: 'Invalid token' };
  }
}
```

### 2. 更新所有管理员接口

将4个管理员工单接口的权限检查逻辑统一替换为：

```typescript
// 验证管理员权限
const adminCheck = verifyAdminToken(request);
if (!adminCheck.valid) {
  const status = adminCheck.error === 'Forbidden' ? 403 : 401;
  return new Response(JSON.stringify({ error: adminCheck.error }), {
    status, headers: { ...corsHeaders, 'Content-Type': 'application/json' }
  });
}
```

### 3. 修改的接口

- `GET /api/admin/tickets` - 管理员获取所有工单
- `GET /api/admin/tickets/:id` - 管理员获取工单详情
- `POST /api/admin/tickets/:id/reply` - 管理员回复工单
- `PATCH /api/admin/tickets/:id/status` - 管理员更新工单状态

## 技术要点

1. **Token验证方式**：直接解析 token payload 检查 `role` 字段，而不是查询数据库
2. **代码复用**：创建 `verifyAdminToken` 辅助函数，避免重复代码
3. **错误处理**：区分 401 Unauthorized 和 403 Forbidden 错误
4. **性能优化**：减少不必要的数据库查询
