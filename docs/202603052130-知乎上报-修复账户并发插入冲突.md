# 知乎上报 - 修复账户并发插入冲突

## 问题描述

知乎文章生成成功后，上报到后端时出现数据库错误：
```
D1_ERROR: UNIQUE constraint failed: accounts.platform_id, accounts.account_id: SQLITE_CONSTRAINT
```

从日志可以看到：
1. 文章AI生成成功，提取到token统计信息
2. 准备上报文章到后端
3. 后端返回500错误，提示账户表UNIQUE约束冲突

## 根本原因

在 `/api/articles/report` 接口中，账户插入逻辑存在竞态条件：

```typescript
// 旧代码（有问题）
if (!accountDbId) {
    await env.DB.prepare(
        'INSERT INTO accounts (...) VALUES (...)'  // 普通INSERT
    ).bind(...).run();
}
```

当两个并发请求同时检查"账户不存在"时，都会尝试INSERT，导致第二个请求违反UNIQUE约束。

## 解决方案

### 1. 修复第一处账户插入（2920-2970行）

使用 `INSERT OR IGNORE` 替代普通 `INSERT`，并在插入后再次查询确保获取到ID：

```typescript
if (!accountDbId) {
    // 使用 INSERT OR IGNORE 避免并发插入冲突
    const result = await env.DB.prepare(
        `INSERT OR IGNORE INTO accounts (platform_id, account_id, user_id, account_name, avatar_url, extra_info, updated_at)
         VALUES (?, ?, ?, ?, ?, ?, ?)`
    ).bind(
        platformId, 
        account.id, 
        userId,
        account.name || 'Unknown', 
        account.avatar || '', 
        JSON.stringify(account.extra || {}),
        Math.floor(Date.now() / 1000)
    ).run();
    
    // 如果 INSERT OR IGNORE 没有插入（因为已存在），last_row_id 会是 0
    // 所以需要再次查询
    if (result.meta.last_row_id) {
        accountDbId = result.meta.last_row_id;
    } else {
        accountDbId = await env.DB.prepare(
            'SELECT id FROM accounts WHERE platform_id = ? AND account_id = ?'
        ).bind(platformId, account.id).first('id');
    }
}

// 始终更新账号信息和 user_id
if (accountDbId) {
    await env.DB.prepare(
        `UPDATE accounts SET user_id = ?, account_name = ?, avatar_url = ?, extra_info = ?, updated_at = ? WHERE id = ?`
    ).bind(
        userId,
        account.name || 'Unknown',
        account.avatar || '',
        JSON.stringify(account.extra || {}),
        Math.floor(Date.now() / 1000),
        accountDbId
    ).run();
}
```

### 2. 修复语法错误

在修复过程中发现代码有重复的 `.bind()` 调用，导致语法错误。已清理重复代码。

### 3. 确认第二处已修复（7581行）

第二处账户插入逻辑已经正确使用了 `INSERT OR IGNORE`，无需修改。

## 工作原理

1. `INSERT OR IGNORE` 在遇到UNIQUE约束冲突时会静默忽略，不抛出错误
2. 如果插入成功，`result.meta.last_row_id` 返回新插入的ID
3. 如果插入被忽略（已存在），`last_row_id` 为0，需要再次查询获取现有ID
4. 无论哪种情况，都能获取到正确的 `accountDbId`
5. 最后统一执行UPDATE确保账户信息最新
