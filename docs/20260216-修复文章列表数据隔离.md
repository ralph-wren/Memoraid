# 修复：文章列表未按账号隔离问题

## 问题原因
原有的系统设计中，`accounts` 表（存储第三方平台账号信息）没有与 `users` 表（存储 Memoraid 用户信息）进行关联。同时，后端 API (`/api/articles`) 在查询数据时，没有验证当前登录用户的身份，也没有根据用户 ID 进行过滤，导致所有用户都能看到系统中存储的所有文章数据。

## 修复内容

### 1. 数据库 Schema 变更
创建了迁移脚本 `backend/migration-user-isolation.sql`，用于在 `accounts` 表中添加 `user_id` 字段。

### 2. 后端代码修改 (`backend/src/index.ts`)
- **添加鉴权辅助函数**：新增 `getUserIdFromRequest` 函数，用于从请求头的 `Authorization` Token 中解析用户 ID。
- **修改 `/api/articles`**：增加了用户登录验证，并在 SQL 查询中添加了 `AND acc.user_id = ?` 条件，只返回归属于当前用户的文章。
- **修改 `/api/articles/stats`**：增加了用户登录验证和数据过滤，统计数据现在只包含当前用户的文章。
- **修改 `/api/accounts`**：增加了用户登录验证和数据过滤，只返回当前用户绑定的账号。
- **修改 `/api/articles/report`**：
    - 增加了用户登录验证。
    - 在创建新账号时，自动将其绑定到当前用户 (`user_id`)。
    - 在更新现有账号时，如果该账号尚未绑定用户（旧数据），自动将其绑定到当前用户。

## ⚠️ 必须执行的操作

为了使修复生效，您必须对生产环境数据库执行 Schema 迁移。请按照以下步骤操作：

1.  **进入 Cloudflare D1 控制台** 或使用 Wrangler 命令行。
2.  **执行 SQL 脚本**：运行 `backend/migration-user-isolation.sql` 中的 SQL 语句。

如果您使用 Wrangler 命令行，可以在项目根目录下运行：

```bash
npx wrangler d1 execute memoraid-db --file=backend/migration-user-isolation.sql --remote
```

（请将 `memoraid-db` 替换为您实际的数据库名称，如果在 `wrangler.toml` 中配置不同的话）

### 注意事项
- **旧数据处理**：执行 SQL 添加列后，现有的账号数据 `user_id` 默认为 `NULL`。这些数据在新的 API 逻辑下将**暂时不可见**。
- **自动修复旧数据**：当您再次使用插件触发一次文章发布或数据上报（调用 `/api/articles/report`）时，后端会自动将相关的账号绑定到您当前登录的用户上，旧数据即可恢复显示。
