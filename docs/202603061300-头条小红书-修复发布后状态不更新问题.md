# 修复头条和小红书发布后状态不更新问题

## 问题描述

用户反馈头条和小红书在发布文章后，管理后台的状态仍然显示"已生成"而不是"已发布"。

### 问题现象

1. **头条**：AI生成文章后上报成功（status: 'generated'），但发布后没有看到任何content script的日志，状态没有更新为"已发布"
2. **小红书**：同一篇文章产生两条记录，AI生成时上报一条，发布时又上报一条新记录，而不是更新原记录

## 问题分析

### 头条问题

从用户提供的日志分析：
- 文章生成成功，上报成功（status: 'generated', generatedId: 'gen_xxx'）
- 打开了头条发布页面：`Opened Toutiao publish page, waiting for content script to fill...`
- **但是没有看到任何来自 `src/content/toutiao.ts` 的日志**

这说明 content script 可能没有被正确加载或执行。

### 小红书问题

小红书有两次上报：
1. AI生成时上报 (status: 'generated', generatedId: 'gen_xxx')
2. 发布时上报 (status: 'published')，但第二次上报没有正确传递 `generatedId` 和 `tokenUsage`

## 解决方案

### 头条修复

在 `src/content/toutiao.ts` 的 `fillContent` 函数中添加详细的调试日志：

1. 在函数开头添加初始化日志
2. 记录 Storage 数据
3. 记录待发布数据详情
4. 在 `reportOnce` 函数中添加上报信息日志
5. 在 `maybeReport` 函数中添加检查状态日志


### 小红书修复

在 `src/content/xiaohongshu.ts` 中：

1. 在 `clickPublishButton` 函数中提前读取 `generatedId`
2. 在 `installPublishReporting` 函数中：
   - 添加防重复上报标志 `hasReported`
   - 读取 `generatedId` 和 `tokenUsage`
   - 传递完整数据到 `reportArticlePublish`
   - 添加调试日志

## 修改的文件

- `src/content/toutiao.ts` - 添加调试日志，帮助诊断为什么content script没有被加载
- `src/content/xiaohongshu.ts` - 修复重复上报问题，确保传递generatedId

## 测试步骤

### 头条测试

1. 重新加载扩展
2. 在头条页面生成并发布文章
3. 查看浏览器控制台日志，应该看到：
   - `[Toutiao] Content script 已加载，检查待发布数据...`
   - `[Toutiao] Storage 数据:` 
   - `[Toutiao] 找到待发布数据:`
   - 发布后应该看到 `[Toutiao] maybeReport 检查:`
   - 如果找到URL，应该看到 `[Toutiao] 准备上报文章:`
4. 在管理后台确认状态是否更新为"已发布"

### 小红书测试

1. 重新加载扩展
2. 在小红书页面生成并发布文章
3. 查看浏览器控制台日志，应该看到：
   - `[Xiaohongshu URL Monitor] 准备上报文章:`
4. 在管理后台确认是否只有一条记录，状态是否为"已发布"

## 注意事项

1. 如果头条仍然没有日志，可能的原因：
   - Content script没有被加载（manifest配置问题）
   - `pending_toutiao_publish` 数据没有被正确保存
   - 页面URL不匹配content script的匹配规则

2. 所有平台的上报逻辑都需要传递 `generatedId` 和 `tokenUsage`，用于关联AI生成的记录和更新状态
