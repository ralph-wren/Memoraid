# 定价页面充值弹窗逻辑修复

## 问题描述

定价页面的充值弹窗与个人中心充值弹窗的逻辑和用户体验不一致：

1. **配色不一致**：定价页面使用蓝色，个人中心使用深色主题
2. **交互流程不一致**：
   - 定价页面：点击"立即充值"按钮直接创建订单，然后才显示弹窗
   - 个人中心：点击"充值"按钮先打开弹窗，用户选择套餐后点击"立即支付"才创建订单
3. **二维码显示时机不一致**：定价页面的二维码在最后才出现，而个人中心在订单创建成功后立即显示
4. **弹窗大小和字体不一致**：定价页面使用固定像素值，个人中心使用CSS变量和相对单位

## 解决方案

### 1. 修改配色
将定价页面充值弹窗的配色从蓝色改为深色（#0f172a），与个人中心保持一致。

### 2. 修改交互流程
修改 `openPricingRecharge()` 函数：
- 点击"立即充值"按钮时，直接打开弹窗（不创建订单）
- 在弹窗中显示套餐选择界面
- 用户点击"立即支付"按钮时才调用 `createPricingOrder()` 创建订单

### 3. 优化订单创建逻辑
修改 `createPricingOrder()` 函数，使其与个人中心的 `createOrder()` 逻辑完全一致：
- 检查用户登录状态（未登录跳转到登录页）
- 显示"正在创建支付订单..."提示
- 创建订单成功后预加载二维码图片
- 立即显示二维码和支付界面
- 开始轮询支付状态

### 4. 完善支付状态检查
重构支付状态检查逻辑，拆分为多个函数：
- `fetchPricingPaymentStatus()`：获取支付状态
- `handlePricingPaidOrder()`：处理支付成功
- `checkPricingPayment()`：自动轮询检查
- `checkPricingPaymentStatus()`：手动检查（点击按钮）
- `updatePricingPaymentStatus()`：更新状态提示
- `preloadPricingQrcode()`：预加载二维码图片

### 5. 完善重置逻辑
修改 `resetPricingPayment()` 函数：
- 停止支付轮询
- 清空订单ID
- 重置界面状态（显示套餐选择，隐藏支付界面）
- 清空二维码
- 重置状态提示文本和颜色
- 启用"刷新状态"按钮

### 6. 统一弹窗样式和字体
修改CSS样式，使用CSS变量和相对单位：
- 弹窗背景：`var(--surface)` 替代 `#fff`
- 弹窗圆角：`24px` 替代 `20px`
- 弹窗宽度：`90%` 替代 `100%`
- 弹窗阴影：`var(--shadow-lg)` 替代固定值
- 标题字体：`1.125rem` 替代 `20px`
- 套餐金额字体：`1.2rem` 替代 `24px`
- 套餐额度字体：`0.9rem` 替代 `14px`
- 边框颜色：`var(--border)` 和 `var(--border-light)` 替代固定颜色
- 文本颜色：`var(--text)`、`var(--text-secondary)`、`var(--text-muted)` 替代固定颜色
- 激活状态：使用 `var(--accent)` 和蓝色渐变

修改HTML内联样式：
- 标题字体大小：`0.95rem`
- 二维码边框：`var(--border-light)` 并添加白色背景和内边距
- "选择其他金额"字体：`0.85rem` 替代 `0.8rem`

## 注意事项

- 定价页面和个人中心的充值弹窗现在使用完全一致的样式、字体和用户体验
- 所有支付相关的函数都添加了 `pricing` 前缀，避免与个人中心的函数冲突

- 使用相对单位（rem）确保字体大小响应式适配
- 支付成功后会自动关闭弹窗，如果在用户中心页面会自动刷新数据
