# 小红书发布上报修复 - 标题和 Token 显示问题

## 问题描述
小红书文章发布后，在管理后台显示的标题是"小红书文章"（默认值），而不是实际的文章标题，并且 Token 消耗数据也没有显示。

## 根本原因
在 `src/content/xiaohongshu.ts` 中，存在两个上报点：

1. **clickPublish 函数**：点击发布按钮时立即上报
2. **URL 监听器**：检测到 `published=true` 参数时再次上报

问题流程：
1. `clickPublish` 函数点击发布按钮
2. 读取 `sessionStorage` 中的标题和 token 数据
3. 上报到后端
4. **清除 sessionStorage 中的数据**（问题所在！）
5. 页面跳转到 `?published=true`
6. URL 监听器检测到跳转，尝试再次上报
7. 但此时 `sessionStorage` 中的数据已被清除
8. 使用默认值"小红书文章"和空的 token 数据

## 解决方案
不要在 `clickPublish` 函数中清除 `sessionStorage` 数据，让 URL 监听器在最终上报后再清除。

### 修改代码

```typescript
// 修复前：
// 如果成功上报，清除保存的标题和token数据
if (pendingTitle) {
    sessionStorage.removeItem('memoraid_pending_title');
}
if (tokenUsageStr) {
    sessionStorage.removeItem('memoraid_token_usage');
}

// 修复后：
// 修复：不在这里清除数据，让 URL 监听器在检测到 published=true 后再清除
// 这样可以确保标题和 token 数据在最终上报时仍然可用
// if (pendingTitle) {
//     sessionStorage.removeItem('memoraid_pending_title');
// }
// if (tokenUsageStr) {
//     sessionStorage.removeItem('memoraid_token_usage');
// }
```

### 数据流程（修复后）

1. `autoFillContent` 函数保存标题和 token 到 `sessionStorage`
2. `clickPublish` 函数点击发布按钮
3. 读取 `sessionStorage` 中的数据并上报
4. **不清除数据**（关键修改）
5. 页面跳转到 `?published=true`
6. URL 监听器检测到跳转
7. 再次读取 `sessionStorage` 中的数据（此时数据仍然存在）
8. 上报正确的标题和 token 数据
9. **清除 sessionStorage 数据**（在最终上报后）

## 为什么有两次上报？

小红书的发布流程比较特殊：
1. 点击"发布"按钮后，页面不会立即跳转
2. 需要等待一段时间（服务器处理）
3. 然后页面才会跳转到 `?published=true`

因此需要两个上报点：
- `clickPublish`：立即上报，让用户知道已经点击了发布
- URL 监听器：最终上报，确认发布成功

但只有 URL 监听器的上报才应该清除数据，因为这是最终的确认。

## 注意事项
1. 这个修复同时解决了标题和 Token 两个问题
2. 不影响其他平台的上报逻辑
3. `generatedId` 不会被清除，因为可能需要多次上报

## 相关问题
- 如果其他平台也有类似的双重上报机制，需要注意数据清除的时机
- `sessionStorage` 的数据在页面刷新后会保留，但关闭标签页后会清除
