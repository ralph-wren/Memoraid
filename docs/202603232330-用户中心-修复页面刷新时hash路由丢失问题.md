# 用户中心页面刷新时hash路由丢失问题修复

## 问题描述
用户反馈：在用户中心的定时任务页面（https://memoraid.dpdns.org/user#tasks）刷新时，页面会跳转到文章列表页面，而不是保持在定时任务页面。

## 问题原因
1. `init()` 函数中没有读取URL的hash来决定显示哪个Tab
2. 导航项同时使用了 `href="#xxx"` 和 `onclick="switchTab('xxx')"` 事件，导致路由逻辑混乱
3. 页面初始化时总是默认显示文章列表Tab，忽略了URL中的hash参数

## 解决方案

### 1. 修改init函数，支持hash路由
```javascript
async function init() {
    const isAuth = await checkAuth();
    if (isAuth) {
        // 根据URL hash决定显示哪个Tab（默认为articles）
        const hash = window.location.hash.slice(1) || 'articles';
        switchTab(hash);
        
        // 如果是文章列表Tab，立即显示平台筛选区域（显示加载状态）
        if (hash === 'articles') {
            document.getElementById('platformFilterBar').style.display = 'block';
        }
        
        loadData();
    }
}
```

### 2. 添加hashchange事件监听
```javascript
// 监听hash变化，实现前端路由
window.addEventListener('hashchange', () => {
    const hash = window.location.hash.slice(1) || 'articles';
    switchTab(hash);
});
```

### 3. 移除导航项的onclick事件
将导航项从：
```html
<a href="#articles" class="nav-item" onclick="switchTab('articles')">
```

改为：
```html
<a href="#articles" class="nav-item">
```

这样点击导航项时，浏览器会自动更新URL hash，触发hashchange事件，再调用switchTab函数。

### 4. 修复充值记录emoji显示问题
将 `<span>�</span>` 改为 `<span>💰</span>`

## 实现原理

### 前端路由流程
```
用户访问 /user#tasks
  ↓
init() 读取 hash = 'tasks'
  ↓
switchTab('tasks') 显示定时任务Tab
  ↓
用户点击导航项 href="#articles"
  ↓
浏览器更新 URL hash
  ↓
触发 hashchange 事件
  ↓
switchTab('articles') 显示文章列表Tab
```

### 页面刷新流程
```
用户在 /user#tasks 页面刷新
  ↓
浏览器重新加载页面，保留 hash
  ↓
init() 读取 hash = 'tasks'
  ↓
switchTab('tasks') 显示定时任务Tab
  ↓
✅ 保持在定时任务页面
```

## 优势
1. 符合Web标准的前端路由实现
2. 支持浏览器前进/后退按钮
3. 刷新页面时保持当前Tab状态
4. URL可以直接分享给他人（带hash）
