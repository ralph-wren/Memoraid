# 定时任务 - 修复多篇文章发布覆盖问题

## 问题描述

用户报告定时任务生成 2 篇文章时，实际只发布了 1 篇。第一篇文章还没发布完成，就开始生成第二篇，导致第二篇覆盖了第一篇。

## 问题分析

通过分析日志和代码，发现问题的根本原因：

1. **定时任务循环处理多篇文章**，每篇文章之间只等待 10 秒
2. **每次调用 `handlePublishToWeixin`** 都会：
   - 将数据保存到 `chrome.storage.local` 的 `pending_weixin_publish`
   - 打开或更新编辑器页面
3. **第一篇文章还在填充时**（可能需要 30-60 秒），10 秒后第二篇就开始了
4. **第二篇覆盖了 `pending_weixin_publish` 数据**，导致第一篇文章的内容丢失
5. Content script 检测到 storage 变化，使用新数据（第二篇）填充编辑器

## 问题流程图

```
时间线：
0s    - 第一篇文章开始处理
0s    - 保存 pending_weixin_publish（第一篇数据）
0s    - 打开编辑器页面
2s    - Content script 开始填充第一篇内容
10s   - 第二篇文章开始处理（第一篇还在填充中！）
10s   - 保存 pending_weixin_publish（第二篇数据，覆盖第一篇）❌
10s   - 更新编辑器页面 URL
12s   - Content script 检测到 storage 变化，使用第二篇数据填充 ❌
结果  - 第一篇内容丢失，只发布了第二篇
```

## 解决方案

在定时任务调度器中，添加等待机制，确保每篇文章完全发布完成后，再开始处理下一篇。

### 核心逻辑

1. **调用 `handleInitiateProcess` 后不立即返回**
2. **轮询检查 `pending_${platform}_publish` 是否已清除**
   - Content script 发布完成后会清除 pending 数据
   - 每 2 秒检查一次
   - 最多等待 120 秒（2 分钟）
3. **只有当 pending 数据清除后，才认为发布完成**
4. **然后等待 10 秒，再处理下一篇文章**

### 代码改进

```typescript
// 依次发布到各平台
for (const platform of task.platforms) {
  await taskLog(task.id, 'info', `📤 开始发布到: ${platform}...`);
  try {
    await taskLog(task.id, 'info', `⏳ 正在抓取内容、AI 生成文章并发布...`);
    // 传递 isScheduledTask = true，标识这是定时任务，强制自动发布
    await handleInitiateProcess(platform, tab.id!, true);
    
    // 【修复】等待发布流程完全完成
    // 检查 pending 数据是否已被清除（表示发布完成）
    // 最多等待 120 秒（2 分钟）
    const maxWaitTime = 120000; // 120 秒
    const checkInterval = 2000; // 每 2 秒检查一次
    const startTime = Date.now();
    let publishCompleted = false;
    
    while (Date.now() - startTime < maxWaitTime) {
      await new Promise(r => setTimeout(r, checkInterval));
      
      // 检查 pending 数据是否已清除
      const storageKey = `pending_${platform}_publish`;
      const result = await chrome.storage.local.get(storageKey);
      
      if (!result[storageKey]) {
        // pending 数据已清除，说明发布完成
        publishCompleted = true;
        await taskLog(task.id, 'success', `✅ ${platform} 发布流程已完成`);
        break;
      }
    }
    
    if (!publishCompleted) {
      await taskLog(task.id, 'warn', `⚠️ ${platform} 发布超时（120秒），继续下一个平台`);
    }
  } catch (e: any) {
    await taskLog(task.id, 'error', `❌ 发布到 ${platform} 失败: ${e.message}`);
  }
}
```

  - 最多等待 120 秒，避免无限等待

## 工作原理

### Content Script 的清除逻辑

Content script 在发布完成后会清除 pending 数据：

```typescript
// 在 src/content/weixin.ts 中
// 发布完成后清除 pending 数据
await chrome.storage.local.remove('pending_weixin_publish');
```

### 调度器的等待逻辑

调度器通过轮询检查 pending 数据是否存在：

1. 调用 `handleInitiateProcess` 触发发布流程
2. 每 2 秒检查一次 `pending_weixin_publish` 是否存在
3. 如果不存在，说明 content script 已经清除（发布完成）
4. 如果 120 秒后仍存在，认为超时，继续下一篇

## 优点

1. **可靠性高**：通过 pending 数据的存在与否判断发布状态
2. **不阻塞**：使用轮询而不是阻塞等待
3. **有超时保护**：最多等待 120 秒，避免卡死
4. **日志清晰**：每个步骤都有日志记录
