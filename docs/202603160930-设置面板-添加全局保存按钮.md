# 设置面板 - 添加全局保存按钮并禁用自动保存

## 问题描述

用户反馈：自动发布按钮（`autoPublishAll`）点击开启后，重新打开设置面板发现又关闭了。

## 问题分析

通过控制台日志发现：
1. 自动保存的防抖逻辑（500ms）会在用户操作后自动触发
2. 第一次保存时使用的是旧状态（`false`），第二次才是新状态（`true`）
3. `chrome.storage.onChanged` 监听器会在保存后重新加载设置
4. 多次保存导致状态混乱，最终丢失用户的修改

根本原因：
- 自动保存和手动保存冲突
- storage change 监听器在保存后立即重新加载，覆盖了刚保存的值

## 解决方案

### 1. 完全禁用自动保存功能
- 注释掉自动保存的 `useEffect`
- 移除 `autoSaveStatus` 状态和相关 UI
- 改为只使用全局保存按钮

### 2. 优化全局保存逻辑
- 保存前标记 `isDirtyRef.current = true`，防止 storage change 监听器干扰
- 保存成功后延迟 1 秒才允许监听器重新加载（`setTimeout(() => isDirtyRef.current = false, 1000)`）
- 避免保存后立即被覆盖

### 3. 修复 saveSettings 函数
- 确保 `autoPublishAll` 字段有明确的值（不是 `undefined`）
- 使用 `?? false` 提供默认值
- 添加日志输出，方便调试

## 修改文件

### src/components/Settings.tsx

   - 保存后延迟 1 秒恢复 `isDirtyRef.current = false`
4. 移除底部的自动保存状态提示 UI

### src/utils/storage.ts
1. 修改 `saveSettings` 函数：
   - 确保 `autoPublishAll` 有明确的值
   - 添加日志输出

## 用户体验改进

1. **明确的保存操作**：用户必须点击"保存设置"按钮才会保存
2. **避免状态混乱**：不再有自动保存和手动保存的冲突
3. **清晰的状态反馈**：按钮颜色和文字变化，让用户知道保存状态
4. **防止覆盖**：保存后 1 秒内不会被 storage change 监听器覆盖

## 测试步骤

1. 重新加载插件

6. 关闭设置面板，重新打开
7. 确认"自动发布"开关仍然是开启状态
