# 定时任务添加和编辑回滚问题修复

## 问题描述

用户在添加或编辑定时任务时，修改会被回滚，导致：
1. 点击"添加定时任务"后，新任务出现但立即消失
2. 修改任务配置（如切换发布平台）后，修改不生效，恢复到旧值

## 问题原因

### 根本原因
`Settings.tsx` 中的 `onSettingsChange` 回调函数在保存时使用了闭包中的旧 `settings` 对象，而不是最新的状态。

### 触发流程
1. 用户修改任务配置
2. `ScheduleSettings` 调用 `onSettingsChange(newSettings)`
3. `setSettings` 更新 React 状态
4. `saveSettings` 保存到 storage，但使用的是旧的 `settings` 对象
5. 旧数据覆盖了新修改，导致回滚

### 代码问题

```typescript
// ❌ 错误的实现
onSettingsChange={async (newSettings) => {
  setSettings(prev => ({
    ...prev,
    scheduledTasks: newSettings.scheduledTasks
  }));
  
  // 这里的 settings 是闭包中的旧值！
  await saveSettings({
    ...settings,  // ❌ 旧值
    scheduledTasks: newSettings.scheduledTasks
  });
}}
```

## 解决方案

使用函数式更新，在 `setSettings` 的回调中获取最新状态并保存：

```typescript
// ✅ 正确的实现
onSettingsChange={async (newSettings) => {
  isDirtyRef.current = true;
  
  setSettings(prev => {
    const updated = {
      ...prev,  // ✅ 最新值
      scheduledTasks: newSettings.scheduledTasks
    };
    
    // 在回调中保存最新状态
    saveSettings(updated).then(() => {
      isDirtyRef.current = false;
    });
    
    return updated;
  });
}}
```

## 关键改进

1. **使用函数式更新**：`setSettings(prev => ...)` 确保获取最新状态
2. **在回调中保存**：在 `setSettings` 的回调函数中调用 `saveSettings`，保证保存的是最新数据
3. **异步保存**：不阻塞 UI 更新，提升用户体验
4. **防止重复加载**：使用 `isDirtyRef.current` 标记，防止 `handleStorageChange` 监听器重新加载旧数据

## 测试验证

1. 添加新任务 → 任务正常保存，不会消失
2. 修改任务配置 → 修改立即生效并保存
3. 切换发布平台 → 平台选择正确保存
4. 修改新闻源类型 → 类型切换正确保存

## 技术要点

### React 闭包陷阱
在事件处理函数中直接使用 state 变量会捕获定义时的值（闭包），而不是最新值。解决方法：
- 使用函数式更新：`setState(prev => ...)`
- 使用 ref 存储最新值
- 使用 useEffect 监听变化

### 状态同步策略
1. 立即更新 UI 状态（React state）
2. 异步保存到持久化存储（chrome.storage）
3. 使用标记位防止循环更新
