# 小红书登录状态保持修复

## 问题描述
每次跳转到小红书发布页面时，都需要重新登录，Cookie 没有被正确保存或传递。

## 根本原因
在 `src/background/index.ts` 的 `handlePublishToXiaohongshu` 函数中，存在两个问题：

1. **Cookie sameSite 属性问题**：
   - 原代码使用 `sameSite: 'no_restriction'`
   - 但 Chrome 的类型定义中没有这个值，需要使用类型断言

2. **标签页更新时机问题**：
   - 原代码同时更新 `active` 和 `url` 属性
   - 这可能导致 Cookie 在页面跳转时丢失
   - 还会触发额外的 `reload` 操作，可能清除 Cookie

## 解决方案

### 1. 修复 Cookie sameSite 属性
```typescript
await chrome.cookies.set({
  url: 'https://creator.xiaohongshu.com',
  domain: '.xiaohongshu.com',
  name,
  value,
  path: '/',
  secure: true,
  sameSite: 'no_restriction' as chrome.cookies.SameSiteStatus // 使用类型断言
});
console.log(`[Background] Set Xiaohongshu cookie: ${name}`);
```

### 2. 优化标签页更新逻辑
```typescript
if (existingTabs.length > 0) {
  // 如果有发布页面，优先使用
  const publishTab = existingTabs.find(t => t.url && t.url.includes('/publish/publish'));
  if (publishTab) {
    tab = publishTab;
  } else {
    tab = existingTabs[0];
  }

  // 修复：先激活标签页，再更新 URL，避免 Cookie 丢失
  await chrome.tabs.update(tab.id!, { active: true });
  // 等待标签页激活
  await new Promise(resolve => setTimeout(resolve, 300));
  // 更新 URL
  await chrome.tabs.update(tab.id!, { url: publishUrl });
  console.log('[Background] Updated existing Xiaohongshu tab');
} else {
  // 创建新标签页
  tab = await chrome.tabs.create({
    url: publishUrl,
    active: true
  });
  console.log('[Background] Created new Xiaohongshu tab');
}
```

### 修改要点

1. **分步更新标签页**：
   - 先激活标签页（`active: true`）
   - 等待 300ms 确保标签页激活完成
   - 再更新 URL
   - 避免同时更新多个属性导致的 Cookie 丢失

2. **移除 reload 操作**：
   - 删除了原来的 `chrome.tabs.reload()` 调用
   - 直接更新 URL 即可触发页面加载
   - 避免额外的刷新操作清除 Cookie

3. **添加日志**：
   - 添加 Cookie 设置成功的日志
   - 添加标签页操作的日志
   - 方便调试和排查问题

## 测试建议
1. 确保在设置中配置了小红书的 Cookie
2. 生成一篇小红书文章
3. 观察是否需要重新登录
4. 检查浏览器控制台的日志，确认 Cookie 是否正确设置

## 注意事项
1. Cookie 必须在设置中正确配置
2. Cookie 的格式应该是：`name1=value1; name2=value2; ...`
3. 如果仍然需要登录，检查 Cookie 是否过期
4. 可以在浏览器开发者工具的 Application > Cookies 中查看 Cookie 是否正确设置

## 相关问题
- 如果其他平台（知乎、头条、公众号）也有类似问题，可以参考此修复方案
- Cookie 的 `sameSite` 属性对于跨站请求很重要
- `no_restriction` 允许 Cookie 在所有上下文中发送
