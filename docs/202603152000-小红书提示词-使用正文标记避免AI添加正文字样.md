# 小红书提示词 - 使用[正文]标记避免AI添加"正文"字样

## 修改时间
2026-03-15 20:00

## 问题描述
AI 生成的小红书文章中，经常会在简介后面出现"正文"、"正文:"、"内容:"等中间提示标记，影响文章质量。

## 问题分析
之前的提示词要求：
- 简介后直接开始写正文内容，不需要任何标记
- 严禁添加"正文:"、"内容:"等中间提示标记

但 AI 仍然会偶尔添加这些标记，因为：
1. AI 习惯性地想要标识内容结构
2. 提示词中的"禁止"规则有时会被 AI 忽略
3. 没有给 AI 一个"正确的"标记方式

## 解决方案
采用"疏导"而不是"堵截"的策略：
1. 在提示词中明确要求 AI 使用 `[正文]` 标记
2. 告诉 AI 这个标记会在发布时自动去除
3. 在解析文章时，自动去除 `[正文]` 标记

这样做的好处：
- AI 有了明确的标记方式，不会自己发明其他标记
- `[正文]` 标记格式统一，容易识别和去除
- 和 `[简介]` 标记保持一致，AI 更容易理解

## 修改内容

### 1. 修改小红书提示词（src/utils/prompts.ts）

#### 正文要求部分
```typescript
#### 正文要求（CRITICAL - 必须使用[正文]标记）
- ⚠️ **正文必须在简介之后**！不要跳过简介直接写正文！
- ✅✅✅ **正文必须使用 \`[正文]\` 标记开头**！
  - 简介后空一行，然后写 \`[正文]\`，再开始写正文内容
  - 格式：\`[正文]\` 后面直接跟正文第一段
  - 这个标记会在发布时自动去除，只是用来标识正文开始位置
```

#### 格式示例部分
```markdown
\`\`\`
# 这是标题

[简介]这是简介内容，50-80字，纯文字不带表情

[正文]这是正文第一段，自然流畅的表达

这是正文第二段，继续分享内容

...更多正文段落...

评论区聊聊吧

#话题1 #话题2 #话题3 #话题4 #话题5
\`\`\`
```

### 2. 修改文章解析逻辑（src/background/index.ts）

在移除其他中间提示标记的代码后面，添加移除 `[正文]` 标记的代码：

```typescript
// 移除可能存在的各种中间提示标记（AI有时会自己添加）
// 包括："正文:"、"正文开始"、"内容:"、"以下是正文"、"[正文]" 等
cleanedContent = cleanedContent.replace(/^正文[:：]\s*\n*/gm, '').trim();
cleanedContent = cleanedContent.replace(/^正文开始[。！!]*\s*\n*/gm, '').trim();
cleanedContent = cleanedContent.replace(/^内容[:：]\s*\n*/gm, '').trim();
cleanedContent = cleanedContent.replace(/^以下是正文[:：]?\s*\n*/gm, '').trim();
// 移除 [正文] 标记（小红书专用）
cleanedContent = cleanedContent.replace(/\[正文\]\s*\n?/g, '').trim();
```

## 技术细节

### 正则表达式说明
```typescript
cleanedContent.replace(/\[正文\]\s*\n?/g, '').trim();
```

- `\[正文\]`：匹配 `[正文]` 标记（方括号需要转义）
- `\s*`：匹配 0 个或多个空白字符
- `\n?`：匹配 0 个或 1 个换行符
- `g`：全局匹配（虽然通常只有一个，但保险起见）

### 为什么用 `\\\`` 转义反引号
在模板字符串中，反引号需要用 `\`` 转义。但在提示词中，我们需要显示反引号，所以要用 `\\\`` 三个反斜杠：
- 第一个 `\` 转义第二个 `\`
- 第三个 `\` 转义反引号 `` ` ``
- 最终显示为 `` \` ``

## 优势
1. AI 有了明确的标记方式，不会自己发明其他标记
2. 格式统一，容易识别和处理
3. 和 `[简介]` 标记保持一致，AI 更容易理解
4. 用户看到的最终文章中不会有任何标记

3. 检查正文内容是否完整，没有被误删
