# 用户管理：修复当日新增标识时区问题

## 修改日期
2026-03-10 13:15

## 问题描述
用户反馈两个都是当天注册的用户，但只有一个显示"新"标识，另一个没有显示。

## 问题原因
Cloudflare Workers 默认使用 UTC 时区，而原代码使用 `new Date().setHours(0, 0, 0, 0)` 计算今天0点时，会受到服务器时区的影响。

### 原代码问题
```javascript
// 问题代码：使用本地时区计算
const todayStart = Math.floor(new Date().setHours(0, 0, 0, 0) / 1000);
```

这会导致：
- Cloudflare Workers 在 UTC 时区运行
- 中国用户在 UTC+8 时区
- 时间判断会有8小时的偏差

### 举例说明
假设现在是中国时间 2026-03-10 01:00（凌晨1点）：
- UTC 时间是 2026-03-09 17:00（前一天下午5点）
- 原代码计算的"今天0点"是 UTC 的 2026-03-09 00:00
- 但用户期望的"今天0点"应该是中国时间的 2026-03-10 00:00（对应 UTC 2026-03-09 16:00）

## 解决方案

### 修改后的代码（backend/src/index.ts）

```javascript
// 当前时间戳，用于计算3日/7日文章数和当日新增用户
const now = Math.floor(Date.now() / 1000);
// 计算今天0点的时间戳（使用中国时区 UTC+8）
const chinaOffset = 8 * 60 * 60; // 8小时的秒数
const chinaTime = now + chinaOffset;
// 计算中国时区今天0点的UTC时间戳
const todayStart = Math.floor(chinaTime / 86400) * 86400 - chinaOffset;
```

### 计算逻辑说明

1. **获取当前UTC时间戳**：`now`
2. **转换为中国时间**：`chinaTime = now + 8小时`
3. **计算中国时区的今天0点**：
   - `chinaTime / 86400`：计算从1970-01-01到现在经过了多少天
   - `Math.floor(...) * 86400`：取整后乘以86400，得到今天0点的中国时间戳
   - `... - chinaOffset`：减去8小时，转换回UTC时间戳

### 示例计算

假设现在是中国时间 2026-03-10 14:30：
1. `now` = 1741593000（UTC时间戳）
2. `chinaTime` = 1741593000 + 28800 = 1741621800（中国时间戳）
3. `chinaTime / 86400` = 20157.64（经过了20157天多）
4. `Math.floor(20157.64) * 86400` = 1741564800（中国时区今天0点）
5. `todayStart` = 1741564800 - 28800 = 1741536000（UTC时间戳）

这样，所有在中国时间今天0点之后注册的用户都会显示"新"标识。

## 技术细节

### 时间常量
- `86400`：一天的秒数（24 * 60 * 60）
- `28800`：8小时的秒数（8 * 60 * 60），即 UTC+8 的偏移量

### SQL判断逻辑
```sql
CASE WHEN u.created_at >= ${todayStart} THEN 1 ELSE 0 END as is_new_today
```

- `u.created_at`：用户注册时间（UTC时间戳）
- `todayStart`：中国时区今天0点对应的UTC时间戳
- 如果注册时间 >= 今天0点，则标记为当日新增
